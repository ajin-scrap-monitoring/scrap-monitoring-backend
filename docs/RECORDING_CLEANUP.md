# 날짜 녹화 삭제와 파일 정리 상태

기존 날짜 녹화 목록과 상세 조회 응답에 다음 선택 필드를 제공한다.
로그인한 사용자가 조회할 수 있으며 삭제 요청은 기존 관리자·CSRF 검사를 유지한다.

| 필드 | 값과 의미 |
| --- | --- |
| `deleted_at` | 논리 삭제 시각. 시간대가 포함된 UTC ISO 8601 또는 null |
| `cleanup_state` | `pending`: 정리 대기/진행, `failed`: 정리 실패, `complete`: 서비스 소유 파일 경로 정리 완료, null: 정보 미제공 |
| `cleanup_completed_at` | 파일 경로 정리 완료 시각 또는 null |
| `cleanup_error` | 오류의 `code`와 안전한 안내 문구, 오류가 없거나 미제공이면 null |
| `space_reclaimed` | 현재 null. 실제 저장 공간 회수 여부를 추정하지 않음 |

이 필드가 없는 이전 미디어 응답도 수용하며 백엔드는 null로 반환한다.
null을 정리 성공으로 해석하지 않는다. 미디어의 내부 경로·원격 오류 원문은 전달하지 않는다.
`complete`는 파일 경로 제거 완료다. 열린 파일이나 파일시스템 동작에 따라 물리 공간
반환 시점은 다를 수 있으므로 `space_reclaimed=true`나 실제 회수량을 만들어내지 않는다.

## 삭제 요청과 재조회

기존 `DELETE /api/v2/recordings/daily/{recording_id}`를 사용한다.
정리가 완료되면 204와 빈 본문을 반환한다. 이미 정리한 항목의 재삭제도 미디어 계약에
따라 204다. 권한·I/O 오류의 503을 204로 바꾸지 않는다. 현재 녹화·마감 중이거나
추출 작업이 원본을 사용하면 기존 409를 유지한다.

삭제 요청 뒤 `GET /api/v2/recordings/daily/{recording_id}`로 상태를 확인한다.
503 이후에도 논리 삭제가 반영되어 `status=deleted`, `cleanup_state=failed`일 수 있다.
실패 원인이 해결되면 관리자가 같은 DELETE를 명시적으로 재시도할 수 있다.
목록·상세 조회가 백엔드에서 삭제나 재시도 요청을 대신 실행하지 않는다.

## 삭제 이후 다운로드와 만료 시각

`status=deleted/expired`이면 재생·다운로드 불가로 처리한다.
`export_state`는 미디어에 남아 있는 변환 작업 상태이며 삭제 뒤에도 과거 `ready`나
`failed`가 유지될 수 있다. `ready`만으로 현재 다운로드가 가능하다고 판단하지 않는다.
`expires_at` 역시 원래 보관 기준이 남을 수 있으며 삭제 이후 파일이 존재하는 유효
기한으로 표시하지 않는다. 백엔드는 원천의 과거 값들을 임의로 바꾸지 않는다.

삭제 전에도 다운로드는 녹화 상태와 `export_allowed`, `export_state`, `download_path`를
함께 확인한다. 경로가 있더라도 삭제·만료 이후 콘텐츠 접근의 410을 처리해야 한다.
파일 정리 상태는 다운로드 권한이나 영상 보존 보장이 아니다.
