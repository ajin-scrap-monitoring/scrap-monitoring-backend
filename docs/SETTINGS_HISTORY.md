# 관리자 설정 변경 이력

알림 설정과 피트 설정을 바꾼 관리자 계정·당시 표시 이름·UTC 시각·변경 전후 값·변경 필드를 기록한다.
기존 관리자/조회 사용자 권한과 CSRF·알림 설정 If-Match ETag 계약은 유지한다.
이 기능 적용 뒤의 실제 값 변경부터 기록하며 과거 기록이나 현재값을 바탕으로 이력을 만들지 않는다.

## 기록 범위

| 설정 저장 API | resource | 기록 값 |
| --- | --- | --- |
| PUT /api/v1/settings/alerts | alert_settings | 기존 응답의 version을 제외한 임계치·알림 지연/반복·복구 알림·유형 |
| PUT /api/v1/config/pits/{pit_id} | pit_config | name, total_depth_cm, warning_threshold_percent, critical_threshold_percent |

피트 신규 생성은 operation=create·before=null, 기존 변경은 update와 이전 값을 기록한다.
실제로 달라진 최상위 필드 이름을 changedFields에 기록한다. preCollectionAlert 같은 객체는 객체 전체의 전후 값을 보여 준다.
단위는 기존과 같은 cm·%·분이며 API별 기존 필드 이름도 그대로 유지한다.
같은 값의 재저장·기본값 GET 초기화·거절된 요청·실패한 트랜잭션은 변경 이력에 추가하지 않는다.
같은 값의 알림 설정 저장에도 기존 ETag 버전이 갱신되는 동작은 유지한다.

계정/비밀번호·토큰·쿠키·연락처·원본 요청 본문·미디어 서버 정책은 기록하지 않는다.
변경한 사용자를 요청 본문에서 받지 않고 서버가 확인한 관리자 세션에서 가져온다.
actor.id는 당시 로그인 계정(username), displayName은 당시 표시 이름이다. 이후 표시 이름 변경/계정 비활성화가 과거 기록을 바꾸지 않는다.
계정을 공유하면 사용한 계정까지만 식별할 수 있다. 사용자 이름을 삭제 후 재사용하면 같은 문자열이 다시 쓰일 수 있으므로 사람을 영구 식별하는 근거로 보장하지 않는다.

설정과 이력은 같은 DB 트랜잭션에서 저장한다. 이력 삽입 실패 시 설정도 rollback한다.
피트 변경은 기존 행 잠금과 이전 값 비교를 함께 사용한다. 동시 변경 충돌은409이며 최신값 조회 후 다시 요청한다.
알림 설정의 기존412/428 동시 수정 방지는 그대로다. 깊이·이름만 바꾸는 별도 피트 API도 변경 이력을 남긴다.
설정의 같은 값을 두 API에서 저장했다고 같은 변경을 두 번 기록하지 않는다. API마다 실제 저장한 차이만 한 건 남긴다.

## 관리자 조회 API

`GET /api/v1/settings/history`

로그인한 관리자만 허용한다. 비로그인401, 조회 사용자403. 성공 응답은 Cache-Control:no-store다.
이력 조회는 설정을 초기화하거나 변경하지 않는다. 다음 매개변수는 모두 선택이다.

| 매개변수 | 의미 |
| --- | --- |
| pit_id | 피트 ID 정확히 일치, 최대50자 |
| actor_id | 관리자 로그인 계정 정확히 일치, 최대64자 |
| resource | alert_settings 또는 pit_config |
| from / to | 시간대가 있는 ISO8601, UTC 정규화, from 포함/to 미포함 |
| limit | 기본20, 1..100 |
| cursor | 이전 응답의 nextCursor, 양의64비트 정수의 십진 문자열 |

응답은 items와 nextCursor다. 각 항목은 id(문자열), occurredAt(UTC), actor{id,displayName}, pitId,
resource, operation, before, after, changedFields를 포함한다. nextCursor가 null이면 마지막 페이지다.
항목 ID 내림차순으로 조회하며 다음 페이지는 cursor보다 작은 ID만 읽는다. 필터는 페이지 사이에 동일하게 유지한다.
새 기록이 추가되어도 이미 읽은 항목이 다음 페이지에 다시 포함되지 않는다. 전체 건수와 임의 페이지 번호는 제공하지 않는다.
이름·계정·설정 문자열은 텍스트로 표시하고 HTML로 해석하지 않는다.
이력 항목의 수정/삭제 API는 제공하지 않는다. 일반 이벤트/수거/알림 이력과 CSV API에 섞지 않는다.
화면의 별도 설정 변경 이력 표/필터 연결은 프론트 작업이며 백엔드 추가만으로 현재 화면에 자동 표시되지는 않는다.

## 저장·배포·복구

`0005_settings_history` migration이 새 테이블과 조회 인덱스를 추가한다. 기존 테이블의 데이터·설정·원문은 수정하지 않는다.
현재 상태와 과거 변경을 구분하기 위해 새 이력 테이블은 빈 상태로 시작한다. 별도 역사 복원·일괄 보완 작업은 없다.
사용자·피트 FK로 과거 기록을 연쇄 삭제하지 않는다. 애플리케이션이 기록을 추가하며 API는 읽기만 제공한다.
DB 관리자의 직접 변경이나 계정 공유를 막는 변조 방지 저장소는 아니다. 자동 이력 삭제·보관 정리 작업도 이번에는 추가하지 않는다.
백업/복원과 데이터 이전은 기존 전 테이블 검증에 이 테이블·ID 시퀀스·JSON 전후 값을 포함한다.

실서버 적용 전 검증된 백업/복원 기준과 기존 Compose/env/DB 역할을 보존한다. [DB migration 절차](DB_MIGRATIONS.md)를 따라
백엔드 쓰기를 중지하고 한 실행자만 migration→schema check를 수행한 뒤 새 이미지를 시작한다.
자동 downgrade는 제공하지 않는다. 구버전 앱의 schema guard는 새 버전을 거절하므로 이미지 교체만으로 되돌리지 않는다.
롤백이 필요하면 DB 백업 복원과 대응 이미지·설정 복구를 함께 검토한다. 이 문서는 실제 배포·DB 변경을 실행한 보고가 아니다.
