# 수거 임계율 예상 도달과 자동 수거 주기

`GET /api/v2/monitoring/fill-forecast?pit_id=pit-demo`는 최근 적재율의 증가 추세가 이어진다는 조건에서 **현재 설정된 수거 임계율**에 도달할 시각을 추정한다. 100% 도달이나 기계팔 작업 완료 시각을 뜻하지 않는다. 기존 로그인 세션과 피트 연결을 사용하며 `Cache-Control: no-store`로 응답한다. 조회는 수거·경보·이메일·촬영 작업을 실행하거나 기록을 추가하지 않는다.

## 프론트 연결 계약

| 필드 | 의미 |
| --- | --- |
| `state` | `AVAILABLE`: 계산 가능, `REACHED`: 이미 임계율 도달, `UNAVAILABLE`: 계산 불가 |
| `computedAt / validUntil` | UTC ISO 8601 계산 시각/사용 기한. 기한이 지나거나 현재 측정이 무효하면 이전 예측을 숨긴다 |
| `currentLoadPercent / targetThresholdPercent` | 계산에 사용한 현재 적재율/설정 임계율(%) |
| `expectedThresholdAt` | 예상 도달 UTC 시각. 계산 불가이면 null |
| `remainingSeconds` | 계산 시각 기준 남은 초. null과 유효한0초를 구분 |
| `inputSource / simulated` | 현재 계산 입력의 출처와 시뮬레이션 여부 |
| `method` | `RECENT_LINEAR_TREND_V1` |
| `windowFrom / windowTo / sampleCount` | 요청한 최근10분 범위. 최소 표본 충족 시 실제 사용한 첫/마지막 관측 시각과 표본 수 |
| `increasePercentPerMinute` | 회귀 기울기(%p/분). 음수·0일 수 있고 그때 미래 도달 시각은 null |
| `trendRSquared` | 추세의 직선 적합도0..1. 적중 확률이나 신뢰구간이 아님 |
| `reasonCodes` | 측정 불가, 수거 진행, 자료 부족, 증가하지 않음, 불안정 등 계산 불가 이유 |

`AVAILABLE`이면 예상 시각을 화면의 시간대로 변환하고 남은 시간은 서버 계산 시각 기준으로 표시한다. `REACHED`는 미래 예측 시각 대신 “임계율 도달”로 표시할 수 있다. `UNAVAILABLE`이면 사유를 표시하고 숫자나 시각을 임의로 채우지 않는다. `validUntil`은 계산 후60초와 현재 관측의 TTL 만료 중 빠른 시각이며, 측정 불가 응답은 계산 시각에 만료한다. 기존 snapshot과 함께 갱신하여 단절 후 오래된 예상 시각을 유지하지 않는다. API 추가만으로 기존 프론트의 고정 미지원 표시는 바뀌지 않으며 담당자의 조회·매핑 연결이 필요하다.

## 계산 규칙과 한계

- 기존 분 이력의 대표값을 최근10분 범위로 조회한다(최대11개 분). 최신 관측은 한 번만 포함한다. 같은 출처·방법·시뮬레이션 여부의 유효 값과 실제 생성/관측 시각이 있어야 한다. 과거에 저장하지 않은 시각은 복원하지 않는다.
- 유효하지 않은 분, 그 분의 무효 표본, 출처·방법 변경, 90초를 넘는 관측 간격, 관측 시각 역전은 이전 추세를 끊는다. 이전 대표값보다1%p를 초과해 내려가도 새 구간으로 시작한다. 이 감소량은 예측용 개발 규칙이며 별도의 높이 기반 수거 감지 임계치나 실측 오차 기준이 아니다.
- 마지막 수거 활동 이전 자료를 제외한다. 자동 감지가 켜져 있고 수거 후보/진행 중 또는 현재 감지 상태를 확인할 수 없으면 미래 시각을 계산하지 않는다. 조회 중 새 관측이 이력에 들어와 현재값과 시점이 달라진 경우에도 재조회를 요청하는 사유로 null을 반환한다.
- 최소3개 관측, 최소60초의 기간이 있어야 한다. 실제 관측의 경과 초와 적재율로 최소제곱 직선을 계산한다. 기울기가 양수이고 R²≥0.8인 경우 `(목표 임계율 - 현재 적재율) / 초당 증가량`으로 계산하며 남은 초는 올림한다. 부동소수점 연산의 극소 오차만 보정한다. 24시간을 넘는 예측은 반환하지 않는다.
- 도달/초과 상태는 관측 당시 이미 도달했다는 뜻으로 계산 시각과 남은0초를 반환한다. 실제 과거 최초 진입 시각을 새로 추정하지 않는다.
- 빈 이력·필터 준비·정체·감소·불규칙 투입·수거 직후에는 계산값이 없을 수 있다. 분 대표값 기반으로 단순 외삽한 예상이며 미래 투입 속도·현장 정확도·기계팔 완료를 보장하지 않는다. 이 예측으로 기존 상태 판정·수거 감지·알림 쿨다운을 변경하지 않는다.

## 자동 수거 종료 기준 평균 주기

기존 `GET /api/v2/monitoring/collection-summary?pit_id=pit-demo&window_days=30`에 다음 필드를 추가한다.

| 필드 | 의미 |
| --- | --- |
| `settledCollectionsInWindow` | 조회 기간 안의 자동 종료 시각 수(같은 시각 중복 제외) |
| `settledCycleCount` | 사용한 종료→다음 종료 간격 수, 종료 n개이면 max(0,n-1) |
| `averageSettledCollectionCycleSeconds` | 자동 종료 간격 평균(초). 최소 종료2개 필요 |
| `settledCycleReasonCodes` | 종료 기록 부족 또는 감지 기준 미설정 사유 |

같은 피트·현장·장치와 현재 감지 기준의 `COLLECTION_SETTLED`만 사용한다. 양 끝 종료가 조회 기간 안인 간격만 계산하며 기간 양 끝은 포함한다. 미래·다른 장치·이전 감지 기준·수거 시작·관리자 확인을 섞지 않는다. `(마지막 종료 - 첫 종료) / settledCycleCount`를 사용한다. 기록이 부족하면 null이며0초로 대신하지 않는다. `detectionProfile`로 FIELD/SIMULATION을 구분한다.

기존 `averageCollectionCycleSeconds`는 관리자 완료 확인 기준, `averageDetectedCollectionCycleSeconds`는 자동 시작 기준으로 그대로 유지한다. 새 “평균 수거 주기” 카드에 자동 종료 기준 값을 쓰면 화면에도 기준을 명시한다. 감지를 껐더라도 동일 기준의 저장된 종료 이력이 남아 있으면 과거 통계는 조회할 수 있다. 새 평균을 위해 가짜 수거 완료 기록을 만들지 않는다.

예상 도달과 평균 주기는 다른 값이다. 평균 주기가 있다고 해당 시간을 예상 도달로 복사하지 않는다. LiDAR·활성 경보 등과 함께 프론트 담당자에게 이 문서를 전달한다.
