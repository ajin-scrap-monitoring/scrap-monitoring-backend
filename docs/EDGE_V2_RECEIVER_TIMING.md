# 엣지 v2 수신 지연 진단

수신 지연을 조사할 때 `EDGE_V2_RECEIVER_TIMING_ENABLED=true`를 짧은 기간 적용하면
인증·스키마 검증을 통과해 수신 함수에 진입한 POST 요청마다 고정 크기의 JSON 로그를 남긴다.
기본값은 false다. `EDGE_V2_RECEIVER_TIMING_MIN_MS`는 로그를 남길 요청의 최소 전체 처리
시간(ms, 기본 0, 최대 60000)이다. 전체 흐름과 순서 역전을 비교하려면 0으로 관측한다.
INFO 로그가 활성화되어 있어야 하며, 적용 환경의 기존 로그 용량·회전 정책을 유지한다.
관측 후 비활성화한다. 공개 저장소에 실제 로그를 올리지 않는다.

기존 응답·중복 ACK·저장 시각·순서 보호·계산 기준을 유지하며 DB 변경은 없다.
진단 기능 구현·서버 반영·진단 설정 활성화·실제 관측은 별도 단계다.

## 시간의 경계

로그 `event`는 `edge_v2_receiver_timing`이다. `route_started_at`은 FastAPI 라우트 처리 시작의
UTC 시각이며 요청 본문 수신·파싱·인증 전에 측정한다. TCP 최초 도착이나 프록시 도착 시각은
아니다. `route_completed_at`은 응답 객체가 준비된 시각이며 실제 클라이언트 ACK 수신 시각이나
응답 전송 완료 시각이 아니다. `total_ms`와 각 구간의 시간은 벽시계 변경에 영향을 받지 않는
단조 시계로 측정한다.

`validation_ms`는 본문 수신·파싱·인증·스키마 검증 후 수신 함수에 진입할 때까지다.
수신 함수 내부의 추가 검사도 전체 시간에 포함된다.

`phases_ms`의 각 값도 ms다. 실행되지 않은 단계는 없으며 실패한 단계도 소요 시간을 기록한다.

| 구간 | 포함 범위 |
| --- | --- |
| body_hash | 멱등성 비교용 원문 해시 계산 |
| receipt_lookup | 기존 접수 기록 조회, DB 연결 확보 대기 포함 가능 |
| projection_lock | 장치별 투영 행 확보 및 잠금 획득. DB 왕복·실행·대기를 포함하며 순수 잠금 대기만의 값은 아님. compact 모드에서 사용 |
| receipt_flush | 최초 접수 행 flush |
| artifacts | 불변 근거 확인·저장 |
| projection | 최신 관측·시간 창·이력 등의 투영 처리 |
| projection_flush | 투영 결과 flush |
| commit | 트랜잭션 commit |

전체 시간에는 위 구간 외 응답 검증·직렬화·오류 처리·rollback 등이 포함될 수 있다.
진단 로그 출력 자체와 이후 ASGI 응답 전송 시간은 `total_ms`에 포함하지 않는다.
중복 요청은 기존 접수 조회만으로 끝날 수 있으며 commit 단계가 없다고 실패는 아니다.
`http_status`로 최초 201·중복 200·오류 응답을 구분한다. 로그 기록 실패는 ACK를 바꾸지 않는다.

기존 ACK의 `received_at`은 장치별 투영 잠금 획득 이후 기록된다. 이를 HTTP 최초 도착 시각이나
클라이언트가 ACK를 받은 시각으로 해석하지 않는다. `generated_at`은 발신자가 제공한 시각이라
발신자와 서버의 시계가 대조되지 않았다면 시각 차이를 순수 통신 지연으로 확정하지 않는다.

## 메시지 대조와 정보 보호

`message_type`은 검증된 모델 종류(Measurement, Assessment, StatusReport, Configuration)다.
측정에는 `delivery_kind`(PERIODIC/EVIDENCE), 판단에는 `assessment_type`(STATE/EVENT)을 기록해
서로 다른 전송 경로를 구분한다. `generated_at`은 해당 메시지의 생성 시각이다.

메시지 ID는 UTF-8 바이트의 SHA-256인 `message_sha256`으로 기록한다. 담당자는 자신의 원본
ID에서 같은 해시를 계산해 대조할 수 있다. 같은 ID는 장치 범위 안에서만 멱등성이 있으므로
`source_sha256`도 함께 사용한다. 이 값은 `[site_id, edge_id]`를 Python의
`json.dumps(..., separators=(",", ":"))` 기본 문자열 이스케이프 방식으로 직렬화한 UTF-8의
SHA-256이다.

Authorization·쿠키·Idempotency-Key 원문·장치 ID 원문·점 배열·SDK 값·인증 실패 본문·DB 예외
메시지는 기록하지 않는다. 인증 또는 스키마 검증에서 거절된 요청은 이 진단 로그 대상이 아니다.

## 조사 순서

1. 서버 반영 후 짧은 관측 기간에 진단을 활성화하고, 송신 담당자도 같은 메시지의 최초 송신·
   재시도·ACK 수신 시각과 PERIODIC/EVIDENCE 구분을 기록한다.
2. 같은 source/message 해시로 서버 라우트 시작·잠금 구간·투영·commit 시간과 맞춘다.
3. 라우트 시작 순서와 저장 순서를 비교하고, 발신자 시계와 대기 기록을 함께 확인한다.
   데이터가 없다는 이유만으로 미전송·영구 손실을 단정하지 않는다.
4. 병목 구간을 확인한 뒤 해당 경로를 수정하고 같은 조건으로 재검증한다.

센서 최신성·계산 창 연속성·화면 유지·운영 경고·손실 복귀 기준은 이 진단으로 변경하지 않는다.
