# 운영 경고 이메일 수신 설정

## 범위와 현재 단계

관리자 수신자 API에 `operationsEmailEnabled`를 추가한다. 기존 수신자는 모두
`false`이며 기존 업무 알림 3종과 전역 알림 정책은 유지한다. 이 변경은 수신 설정과
독립 점검기가 사용할 수신자 캐시까지 제공한다. 디스크 점검, 정기 실행, 중복 방지,
복구 통보 및 메일 발송은 후속 연결이 필요하다. 설정 저장 성공은 감시 가동이나
메일 발송·실제 수신을 뜻하지 않는다. 대시보드 디스크 상태 API는 추가하지 않는다.

## 관리자 API와 화면 연결

기존 `GET /api/v1/notification-recipients`의 각 수신자와 생성·수정 응답에
`operationsEmailEnabled: boolean`이 포함된다. 생성 시 생략하면 `false`, 수정 시
생략하면 기존 값을 보존한다. 문자열, 숫자, `null`은 허용하지 않는다.

프론트는 관리자 수신자 편집에 **운영 경고 이메일 수신** 체크박스를 연결한다.
생성은 기존 POST, 수정은 기존 PATCH와 `If-Match`/ETag를 사용한다.
기존 관리자 권한·세션·CSRF 검증을 그대로 적용하며, 412이면 새 설정을 읽고
사용자에게 재확인을 요청한다. 아직 감시 가동 상태나 시험 발송 성공을 표시하지 않는다.

```json
{"operationsEmailEnabled": true}
```

운영 경고의 유효 수신자는 `enabled=true`, `operationsEmailEnabled=true`,
`channels`에 `email` 포함 조건을 모두 만족해야 한다. `sms`만 선택한 상태에서
운영 이메일을 켜거나, 켜진 상태에서 이메일 채널만 제거하면 422이다.
두 값을 한 요청으로 끄고 이메일 채널을 제거할 수 있다.
수신자 전체 비활성화는 업무·운영 이메일 모두 중지한다.

운영 경고는 업무 `eventTypes`나 `subscriptionMode`의 필터를 사용하지 않는다.
운영 이메일만 받는 수신자를 생성하려면 `subscriptionMode="custom"`,
`eventTypes=[]`, `channels=["email"]`, `operationsEmailEnabled=true`로 지정한다.
`global`은 기존처럼 전역 업무 알림도 구독하므로 운영 전용으로 사용하지 않는다.
이 플래그 변경으로 기존 업무 메일 작업을 생성하지 않는다. 기존 시험 알림 API는
운영 감시 시험 발송으로 간주하지 않는다.

## 웹 앱과 분리된 수신자 캐시

독립 실행 명령은 웹 앱 시작이나 업무 이메일 워커 시작 없이, 읽기 전용 조회로
현재 유효 수신자를 개인 캐시에 투영한다. PostgreSQL 조회 트랜잭션은 READ ONLY,
쿼리 제한 시간은 5초, 전체 조회 제한은 8초이다. 설정용 DB URL은 별도 환경 변수
`OPS_RECIPIENT_DATABASE_URL`로 공급하며 최소 SELECT 권한 계정을 사용한다.
기존 설정 파일이나 비밀 파일을 변경하지 않는다.

```sh
uv run python -m src.app.cli.operations_recipients --cache /private-state/recipients.json
```

DB 정상 조회에서 수신자가 0명이면 캐시도 즉시 빈 목록으로 교체한다. DB 장애나
조회 제한 시간 초과이면 마지막 정상 캐시를 읽되, 기본 최대 24시간만 허용한다.
`--max-age-seconds`는 1~86400 범위이며 캐시 사용으로 생성 시각을 갱신하지 않는다.
따라서 DB 장애 중에는 해제·주소 변경이 즉시 반영되지 않을 수 있고, 최대 캐시
유효 시간 동안 마지막 정상 수신 설정이 남는다. 유효 기간이 끝나거나 파일이 없거나
손상되면 수신 대상을 추정하지 않고 실패한다. 갱신 파일 쓰기 실패도 실패 처리한다.

캐시는 수신자 ID·주소·버전·UTC 생성 시각만 포함하고 최대 1000명/512KiB로
제한한다. 전용 비공개 디렉터리에 저장한다. 파일은 0600으로 원자 교체하며
읽을 때 공개 권한·심볼릭 링크·잘못된 시각을 거부한다. 표준 출력은 수신자 수,
캐시 사용 여부, UTC 생성 시각과 `notificationSent=false`만 출력한다.
주소·DSN·토큰은 출력하지 않는다. 명령 자체는 정기 실행이나 메일 발송을 하지 않는다.
후속 점검기는 단일 실행자로 갱신과 캐시 읽기를 직렬화해야 한다.

## DB 적용과 복귀

새 head는 `0008_operations_recipient`이며 기존 `0007_raw_retention` 다음에
불리언 열 하나를 추가한다. 기존 설정·계정·작업·원문 보관 설정은 변경하지 않는다.
새 코드는 스키마 적용이 필요하므로 검증되지 않은 서버에서 그대로 시작하지 않는다.
이미 완료한 백업 복원이나 과거 마이그레이션을 반복하는 절차가 아니다.

이전 0007 이미지로의 복귀에는 검토된 스키마 복귀가 필요하다. 새 열에 켜진
구독이 하나라도 있으면 downgrade가 중단된다. 명시적으로 구독을 해제하고 검토한
경우에만 새 열을 제거할 수 있다. 자동 downgrade나 자동 구독 해제는 하지 않는다.
서버 적용·정기 감시 설치·메일 발송은 각각 별도로 검증하고 기록한다.
