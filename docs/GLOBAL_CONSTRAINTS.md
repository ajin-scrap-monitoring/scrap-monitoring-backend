# 아진산업 스크랩 모니터링 시스템 백엔드 전역 개발 제약조건 (Global Constraints)

> **문서 코드**: `AJIN-BACKEND-GLOBAL-CONSTRAINTS-001`  
> **기준 문서**: `GOVERNANCE.md`, `백엔드_모니터링_API_아키텍처_설계서.md (v3.1-draft)`, `아진산업_스크랩_적재_모니터링_시스템_전체_프로젝트_계획서.md`  
> **적용 대상**: `ajin-scrap-monitoring` 백엔드 서비스 (`monitoring-backend-service`) 소스 코드, 아키텍처, 데이터베이스 및 자동화 파이프라인 전반  

---

## 1. 개요 및 목적

본 문서는 아진산업 스크랩 적재 모니터링 시스템의 백엔드 서비스(`monitoring-backend-service`)를 구축할 때, 전체 개발 주기 동안 **예외 없이 절대적으로 준수해야 하는 전역 제약조건(Global Constraints)**을 정의한다.

백엔드 개발은 팀 거버넌스 규칙, 전체 시스템 통합 계획, 백엔드 아키텍처 설계서의 원칙을 바탕으로 진행되며, 모든 모듈과 코드는 본 제약조건에 정의된 경계와 규칙을 통과해야 한다.

## 2. 거버넌스 및 Public 저장소 보안 제약조건

1. **Public 저장소 정보 격리 (절대 금지 항목)**
   - 실제 사설 IP 주소, 내부 네트워크 토폴로지, 실제 자격 증명(DB 패스워드, JWT 시크릿, API 키 등)은 소스 코드, 설정 파일, 커밋 이력에 절대 포함하지 않는다.
   - 현장 사진, 실제 공장 내부 치수, 실제 현장 측정 원본 데이터는 커밋하지 않는다.
   - 로컬 검증 및 테스트에는 사전에 정의된 **합성 예제 데이터(Synthetic Data)** 및 규격화된 샘플만 사용한다.
   - 모든 민감 설정은 `.env` 및 로컬 환경변수를 통해서만 주입받으며, `.gitignore`에 의해 버전 관리에서 제외한다.

2. **라이선스 및 소스 이용 조건 명시**
   - 개발 저장소에는 별도의 `LICENSE` 파일을 생성하지 않는다.
   - 루트 `README.md`의 [이용 조건] 섹션에 다음 표준 문구를 고정 명시한다:
     > "이 Repository는 코드 검토와 참고를 위해 Public으로 제공하며 프로젝트 소스 코드에 별도 라이선스를 부여하지 않는다."

3. **Git 브랜치, 커밋 및 PR 거버넌스**
   - 기본 브랜치는 `main`이며, 원격 `main`으로의 직접 Push는 엄격히 금지된다.
   - 작업 브랜치 네이밍: `<type>/<issue-number>-<short-description>`  
     (허용 type: `feat`, `fix`, `ci`, `docs`, `chore`)
   - 커밋 메시지 및 PR 제목: `<type>: <summary>` (한글 요약 허용)
   - PR 병합 방식: **Squash Merge**만 허용 (Merge commit, Rebase merge, Auto-merge 비활성화).
   - PR 본문에는 연동된 Issue를 닫기 위해 반드시 `Closes #<이슈번호>`를 포함한다.

## 3. 아키텍처 및 시스템 경계 제약조건

1. **데이터 경로(Data Path)와 제어 경로(Control Path)의 엄격한 분리**
   - **미디어 스트림 본체(비디오 프레임 바이트) 직접 중계 절대 금지**: 백엔드는 카메라 영상 바이트를 직접 수신하거나 대시보드로 전달하지 않는다. 영상 스트리밍은 카메라/미디어 전용 서비스가 전담한다.
   - 백엔드는 오직 센서 수치 데이터(높이, 적재율, 상태), 실시간 상태 브로드캐스팅, 세션 시청 권한 검증 지원, 녹화 완료 메타데이터 인덱싱 및 제어 API만 처리한다.

2. **비동기 기반 실시간 파이프라인 및 장애 격리**
   - 모든 네트워크 I/O 및 데이터베이스 쿼리는 **완전 비동기(Async I/O)**로 처리한다.
   - 외부 알림 서비스(SMTP, SMS, 메신저 Webhook 등)의 지연이나 일시 장애가 센서 데이터 인입 및 DB 트랜잭션을 블로킹하지 않도록 백그라운드 비동기 태스크로 철저히 격리한다.
   - 대시보드 클라이언트의 연결 단절 시 커넥션 리소스를 즉시 회수하여 메모리 누수를 방지한다.

3. **단일 서비스 자기완결성 (Self-contained)**
   - 엣지 장비나 프론트엔드 대시보드가 구동되지 않은 환경에서도 백엔드 단독으로 빌드, 마이그레이션, 단위/통합 테스트, 실데이터 리플레이 검증이 가능해야 한다.

## 4. 기술 스택 및 개발 환경 제약조건

1. **언어 런타임 및 도구 표준**
   - **Python 3.13** 표준 런타임을 사용한다.
   - 패키지 및 가상환경 관리는 **`uv` (`pyproject.toml`, `uv.lock`)** 단일 도구로 일원화하여 완전히 재현 가능한 빌드 환경을 보장한다.

2. **프레임워크 및 라이브러리 스택**
   - **Web Framework**: FastAPI (현대적인 `async def` 라우터 구조)
   - **데이터 검증 및 직렬화**: Pydantic v2
   - **데이터베이스 ORM**: SQLAlchemy 2.0 (Asyncio 확장) + `asyncpg` (PostgreSQL) / 테스트용 `aiosqlite`
   - **테스트 프레임워크**: pytest + pytest-asyncio
   - **코드 품질 및 정적 분석**:
     - Ruff (Linter & Formatter 통일)
     - mypy (엄격한 정적 타입 검사)

## 5. 도메인 데이터 모델 및 영속화 제약조건

1. **데이터 4대 성격 분리 영속화 원칙**
   - **시계열 상태 메트릭 (Time-series Metrics)**: 센서별(LiDAR 1, LiDAR 2) 거리, 산출 적재 높이(cm), 적재율(%), 센서 연결 및 진단 상태, 타임스탬프.
   - **설정 및 마스터 (Configuration Data)**: 구덩이(Pit) 식별자, 총 깊이, 경고/수거 임계율(%) 등.
   - **운영 및 수거 이력 (Operational Logs)**: 알림 발송 로그(시각, 적재율, 수신 채널, 결과), 현장 수거 작업 이력(작업 시각, 수거 후 잔여 높이, 확인 작업자).
   - **미디어 색인 메타데이터 (Media Index Metadata)**: 녹화 세그먼트 식별자, 시작/종료 시각, 파일 크기 등 구조화된 색인 메타데이터만 저장.

2. **단위 및 시각 표현 표준**
   - 모든 타임스탬프는 **UTC 기준 ISO 8601** (`YYYY-MM-DDTHH:MM:SSZ` 또는 timezone-aware UTC datetime)을 준수한다.
   - 모든 거리 및 높이 수치는 **cm(센티미터)** 단위로 통일한다.
   - 모든 적재율 수치는 **% (0.0 ~ 100.0 범위의 float)** 단위로 통일한다.

## 6. 상태 판정 및 알림 엔진 제약조건

1. **3단계 상태 전이 모델**
   - `NORMAL`: 적재율 < Warning 임계치 (기본 기준: 75% 미만)
   - `WARNING`: Warning 임계치 이상 ~ Critical 임계치 미만
   - `CRITICAL`: Critical(수거 요청) 임계치 이상 (기본 기준: 85% 이상)

2. **채터링(Chattering) 방지 및 쿨다운 정책**
   - `CRITICAL` 상태 진입 시 **즉시 1회에 한하여** 외부 알림 이벤트를 발생시킨다.
   - 발송 직후 지정된 **쿨다운 시간(기본 30분)** 동안은 `CRITICAL` 범위의 수치가 지속 유입되어도 중복 알림을 엄격히 억제한다.
   - **히스테리시스 및 명시적 리셋**: 경계치 부근(예: 84.9% ↔ 85.1%) 센서 노이즈로 인한 잦은 상태 복구를 방지하기 위해, 수치가 기준치 이하로 충분히 낮아지거나 현장 수거 완료 API가 호출되기 전까지 알림 상태를 임의로 초기화하지 않는다.

## 7. 인터페이스 및 통신 프로토콜 제약조건

1. **LiDAR 엣지 인입 인터페이스 (`/api/v1/metrics/ingest`)**
   - 엣지 장비 인증 식별자(Edge Device API Key / Bearer 토큰)를 검증한다.
   - 인입되는 높이, 적재율, 센서 진단 필드의 유효 범위를 Pydantic 스키마로 검증하고 음수나 비현실적 이상값은 필터링 및 진단 플래그를 부여한다.

2. **카메라/미디어 연동 인터페이스 (`/api/v1/media/...`)**
   - 대시보드 사용자의 실시간 영상 시청 권한 확인을 지원한다.
   - 녹화 완료 시 미디어 서비스가 호출하는 구조화된 메타데이터 Webhook 엔드포인트를 제공하고 DB에 기록한다.

3. **대시보드 실시간 및 제어 인터페이스**
   - 저지연 실시간 상태 푸시: WebSocket 또는 SSE(Server-Sent Events) 스트림 지원.
   - 대시보드 차트용 통계 쿼리: 기간별/해상도별 적재 추이 통계 집계 API 제공.
   - 관리자 제어: 임계치(Warning/Critical) 동적 변경 및 현장 수거 완료 확인 처리 API 제공.

## 8. 환경 설정 및 Fail-Fast 수명주기 제약조건

1. **환경 설정 계층화**
   - 포트, 바인드 호스트, 기본 로그 레벨, CORS 정책 등 비민감 설정은 안전한 기본값을 제공한다.
   - 데이터베이스 접속 URL(계정/비밀번호), 인증 토큰 시크릿, 외부 알림 API Key 등은 코드 기본값을 절대 두지 않고 런타임 환경 변수로만 주입받는다.

2. **기동 시 즉각 검증 (Fail-Fast)**
   - 서비스 시작(Startup) 시 필수 환경변수가 누락되었거나 DB 연결 풀 초기화에 실패할 경우, 모호한 에러 없이 즉시 명확한 오류 로그를 출력하고 기동을 중단한다.

## 9. 코드 품질, 정적 검사 및 CI 파이프라인 제약조건

1. **타입 힌트 및 코드 스타일**
   - 모든 함수, 메서드, API 엔드포인트는 엄격한 Python Type Hinting을 적용한다.
   - Ruff 린트/포맷 규칙을 준수하며, 경고나 린트 오류가 남은 상태로 커밋하지 않는다.
   - mypy 정적 타입 분석을 통과해야 한다.

2. **테스트 커버리지 및 실데이터 검증**
   - 단순 단위 테스트(Unit Test) 외에 상태 전이 머신, 쿨다운 타이머, API 엔드포인트 통합 테스트를 구축한다.
   - LiDAR 파트의 실제 센서 수집 샘플 데이터를 재생(Replay)하여 인입부터 DB 적재, 실시간 브로드캐스팅까지의 무결성을 검증하는 리플레이 테스트 스위트를 포함한다.

3. **CI 워크플로우 무결성**
   - GitHub Actions `CI` 워크플로우는 의존성 잠금(`uv.lock`), Ruff, mypy, pytest, Docker build를 필수 통과 단계로 운영한다.
   - 전체 CI job을 우회하거나 생략하는 조건문/경로 필터는 사용하지 않는다.

## 10. OCI 컨테이너 패키징 및 릴리스 제약조건

1. **컨테이너 이미지 사양 및 보안**
   - 베이스 이미지는 경량화된 Linux(`python:3.13-slim` 등)를 사용한다.
   - 컨테이너 내부 프로세스는 반드시 **비루트(Non-root) 사용자** 권한으로 실행한다.
   - 컨테이너 이미지 레이어에 설정 파일(`.env`), 비밀키, 로컬 테스트 산출물을 굽지(bake) 않는다.

2. **GHCR 패키지 및 이미지 태그 규칙**
   - 산출물 경로: `ghcr.io/ajin-scrap-monitoring/monitoring-backend-service` (Public Package).
   - 배포 릴리스 태그: `vMAJOR.MINOR.PATCH`에서 파생한 `MAJOR.MINOR.PATCH`
   - 커밋 추적 태그: `sha-<full-git-sha>`
   - `latest` 태그는 게시하지 않으며, 배포 시에는 SHA-256 Digest(`@sha256:...`) 참조를 원칙으로 한다.
