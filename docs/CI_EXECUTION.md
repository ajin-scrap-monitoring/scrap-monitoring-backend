# CI 실행과 배포 전 확인

전체 `CI`는 main을 대상으로 한 PR에서 자동 실행한다. main push에서는 자동으로 다시
실행하지 않는다. 검사 내용과 `CI` check 이름은 유지한다. CodeQL과 GitHub 보호 규칙은
이 변경에서 수정하지 않는다. 실행하지 않은 검사를 성공으로 표시하지 않는다.

전체 CI를 main에서 다시 실행하려면 Actions → CI → Run workflow에서 main을 선택한다.
CLI에서도 실행할 수 있다.

```sh
gh workflow run ci.yml --ref main
```

수동 실행을 요청했다는 사실과 실제 실행 성공을 구분한다. run의 실제 head SHA,
완료 상태와 결과를 확인한다. 릴리스 워크플로의 기존 검증도 유지한다.

## 배포 근거

main에 자동 CI run이 없는 것은 실패나 성공을 뜻하지 않는다. 다음 근거를 확인한다.

1. 배포할 실제 main SHA와 해당 커밋을 만든 병합 PR을 확인한다.
2. 해당 PR의 마지막 head SHA에서 전체 CI가 실제 성공했는지 확인한다. 이전 head의
   성공이나 다른 PR의 결과를 사용하지 않는다.
3. Git commit API의 `commit.tree.sha`로 PR 마지막 head와 실제 main의 전체 소스 tree가
   같은지 확인한다. commit SHA 자체는 squash 병합으로 달라질 수 있다. PR이 base와
   합쳐진 결과를 검사한다는 점도 확인하며, 검증 대상 소스가 불명확하면 재사용하지 않는다.
4. 실제 main SHA의 CodeQL 성공을 확인한다.
5. 근거가 없거나 소스 tree가 다르면 main에서 전체 CI를 수동 실행하고 실제 성공을 확인한다.
6. 실제 서버 반영은 설정·DB·비밀·마운트 보존, 후보 이미지의 실제 소스 일치와 격리 검증,
   적용 뒤 API·실수신 검증을 별도로 수행한다. PR 검사 성공만으로 배포 완료라고 하지 않는다.

기존에 실제 main SHA에서 전체 CI가 성공한 근거가 있으면 계속 사용할 수 있다.
main의 임의 커밋에 다른 소스의 검사 결과를 붙이거나 검사 범위를 숨기지 않는다.
