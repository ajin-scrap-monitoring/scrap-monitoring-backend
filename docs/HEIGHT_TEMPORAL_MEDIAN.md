# 높이(cm)의 시간 중앙값과 기존 API 필드

백엔드는 검증된 높이 구간별로 시간 중앙값을 계산한다. 대시보드는 기존 `height`, `average`, `minimum`, `maximum` 필드를 그대로 읽는다. 중앙값 계산을 프론트엔드로 옮기거나 별도 필수 높이 필드를 추가하지 않는다.

## 대상과 활성화

- 대상: `GET /api/v2/monitoring/profiles?pit_id=...`의 센서별 높이 곡선. `unit=cm` 유지.
- `EDGE_V2_HEIGHT_MEDIAN_ENABLED=true`: 높이 표시만 시간 필터 적용. 기존 엣지 STATE 판정은 유지한다.
- `EDGE_V2_HEIGHT_FILL_ENABLED=true`: 높이 시간 필터도 함께 활성화하고, 안정화된 높이에서 단면 비율·분 이력·수거 필요 판정을 계산한다.
- 둘 다 기본 false다. compact 저장과 비공개 [검증 높이 기준](LIDAR_HEIGHT_PROFILES.md)이 필요하다. 실제 설치·좌표·바닥·깊이·보정을 확인하기 전 활성화하지 않는다.

기존 v1 snapshot의 높이 프로필은 별도 `m` 계약이다. 이번 변경은 그 경로나 단위를 바꾸지 않는다. 현재 대시보드가 사용하는 모드와 API 호출을 확인해야 하며, 백엔드가 값을 제공하는 것만으로 사용하지 않던 API가 화면에 자동 연결되지는 않는다. 다른 담당자 저장소는 수정하지 않는다.

## 처리 순서

```text
각 스캔의 검증 좌표
  → 공간 구간별 높이(cm) 대표값
  → 같은 구간의 최근 5초, 서로 다른 초의 5개 높이 중앙값
  → 기존 samples[].height에 결과 전달
  → 필터된 구간 높이로 average / minimum / maximum 계산
  → 필요하면 단면 비율 계산 → 이력·수거 필요 판정
```

기본 창은 5초이며 `EDGE_V2_MEDIAN_WINDOW_SECONDS`의 홀수 설정을 따른다. 백엔드 수신 계약은 초당 선택된 스캔 한 개씩이다. 센서가 10Hz로 수집하더라도 그 10개 스캔 전체의 중앙값을 계산한다는 뜻은 아니다. 같은 초에 여러 관측이 도착해도 준비 개수를 늘리지 않는다.

예를 들어 한 구간의 최근 높이가 `100, 100, 100, 100, 200 cm`이면 기존 `height` 값은 `100.0`이다. 높은 값이 지속되면 중앙값도 높아진다. `average`는 시간 평균이 아니라, 시간 필터를 거친 공간 구간 높이들의 평균이다. 중앙값은 오측정 영향을 줄이는 방법이며 현장 정확도를 보증하지 않는다.

응답의 기존 형식 일부:

```json
{
  "unit": "cm",
  "average": 100.0,
  "minimum": 100.0,
  "maximum": 100.0,
  "samples": [
    {"positionRatio": 0.25, "height": 100.0, "valid": true},
    {"positionRatio": 0.75, "height": 100.0, "valid": true}
  ],
  "valuePolicy": "SPATIAL_TEMPORAL_MEDIAN"
}
```

`valuePolicy`는 처리 방법을 구분하는 기존 메타데이터다. 기본 모드의 `SPATIAL_BIN_MEDIAN`도 유지한다. `measuredAt`은 가장 최근 참여 스캔 시각이며, 반환 높이는 시간 창의 대표값이다. 새 메타데이터를 읽지 않아도 높이 숫자를 표시할 수 있다.

## 결측과 무효화

- 유효 높이 5개가 모이기 전이나 한 구간이 결측이면 해당 `height=null`, `valid=false`다. 결측 구간을 과거 높이로 채우지 않는다. 유효한 0cm는 그대로 숫자 0이다.
- 다른 정상 구간의 대표값은 유지할 수 있지만 설정된 coverage를 충족하지 못하면 단면 비율은 null이다. 결측 구간은 연속된 유효 관측을 다시 모아 복구한다.
- 관측 공백 1.5초 초과, 늦은 관측, 설정·보정·기준·깊이·창 크기 변경, 장치 재부팅과 상태 장애는 관련 창을 다시 준비한다. 상태 보고에서 장애가 확인되면 다음 측정 전에도 창을 비운다.
- 최신 좌표·센서·장치·설정·시각 유효성 검사를 매 조회에도 적용한다. 오래된 창의 수치로 현재 장애를 감추지 않는다.
- 재전송, 과거 EVIDENCE, 늦은 메시지와 GET 조회는 새 관측 개수를 늘리지 않는다.

## 저장과 판정

새 테이블이나 migration은 없다. 기존 `edge_v2_latest`에 장비별 `kind=height_window` 한 행을 추가하고, 센서별 제한된 최근 높이 숫자와 시각·구간 위치만 교체 저장한다. 기본은 센서당 최대 5개 관측, 구간 최대 200개다. 원래 점 배열을 이 창이나 분 이력에 추가 저장하지 않는다.

높이 판정 모드의 `summary.rawLoadPercent`는 현재 스캔의 단면 비율, `summary.loadPercent`는 시간 중앙값을 적용한 높이에서 계산한 단면 비율이다. 비율에 두 번째 시간 중앙값을 적용하지 않는다. 표시 높이와 판정 비율이 같은 안정화된 높이를 사용한다. 기본 3초 위험 확인·75/90/85 기준·30분 쿨다운은 유지한다.

방법 식별은 `HEIGHT_SECTION_V2:<digest>`다. 이전 비율 필터의 `HEIGHT_SECTION_V1`과 같은 분 bucket에서 서로 다른 유효 방법이 섞이면 기존 MIXED/null 정책을 따른다. 실제 외부 문자·이메일 발송은 포함하지 않는다.

## 검증

`tests/test_height_median.py`는 실제 HTTP 수신과 기존 높이 응답, 순간 튐·지속 상승·구간 결측·복구·0cm·중복·근거 메시지·다중 관측·표시 전용 모드를 검증한다. 구간별 중앙값 이후 비율을 계산하는 것과, 구간 평균 비율의 중앙값을 계산하는 것의 차이도 확인한다. 필터를 두 번 거쳐 추가 지연이 생기지 않는지 검증한다.
