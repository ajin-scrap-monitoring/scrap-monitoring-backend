# 측정 입력 오류 이력과 복구 확인

이 정책은 이후 수신되는 측정 입력의 운영 이력과 자동 오류 클립에 적용한다.
과거 이력은 수정하지 않는다. 계산 결과, 입력 유효성, 현재 장치 상태와 적재율
판정은 기존 기준을 그대로 사용한다.

- 정상 입력을 확인한 뒤 첫 오류는 즉시 기록한다.
- 같은 장치·현장 배정·설정·계산 방식·입력 출처·실행 세대의 같은 원인은
  새 유효 관측이 10초 동안 연속 확인될 때까지 하나의 오류 구간으로 관리한다.
- 다른 원인이 추가되면 입력 유효성이 이미 false여도 별도 오류를 기록한다.
  기존 원인의 순서 변경이나 부분 집합만으로 새 오류를 만들지 않는다.
- 관측 시각과 서버 수신 시각 모두 10초 이상 이어져야 복구를 기록한다.
  각 관측·수신 간격은 기존 연속성 기준인 1.5초 이하여야 한다. 중단·무효
  입력·역행 시각·반복 관측은 복구 확인을 다시 시작한다. 과거 자료가 한꺼번에
  도착하거나 조회 요청만 반복되는 경우에는 복구를 확정하지 않는다.
- 불가 보고에서 계산 방식이 생략되는 것은 새 방식으로 취급하지 않는다.
  명시적인 새 방식이나 설정·실행 세대 변경은 이전 억제를 재사용하지 않으며,
  새 정상 보고로 과거 구간의 복구를 추정하지 않는다.

원래 true/false 변화는 `MEASUREMENT_VALIDITY_CHANGED`에 그대로 남긴다.
반복 오류와 복구 확인 중의 원본 변화에는 `diagnosticOnly`를 표시한다.
별도 운영 오류·확정 복구에는 `measurementEpisodeEvent`를 표시하며,
이때 `previousValid`와 `currentValid`가 같을 수 있다. 이는 입력의 원본 변화가
아닌 운영 이력임을 나타내며 이전 유효성을 조작하지 않는다. 원인·입력 ID·
관측 ID·출처·현장 배정은 보존한다. 이벤트 목록·CSV·클립 선택은 같은 판정으로
이 기록을 처리하고, 복구 자체로 오류 클립을 생성하지 않는다.

장치별 `EdgeV2Latest` 한 행에 최대 128개의 원인 해시와 복구 확인 시각만 저장한다.
기존 장치 잠금 및 수신 트랜잭션에 포함하므로 재시작에도 유지되고 실패 시 원본
변화와 함께 롤백된다. 정상 입력의 기준이 저장된 뒤에는 이 행을 매 관측마다
갱신하지 않는다. 원인 한도를 넘으면 새 오류를 숨기지 않는 쪽으로 처리한다.

계산 최신성 1초, 최근 5초 중앙값, 스캔 지연 경고 3초, 손실 경고의 정상 1시간
복귀, 프론트 화면 표시 유지 시간과는 각각 별개다. 복구 확인 중이어도 새 유효
입력은 계산에 즉시 사용하며, 끊긴 입력을 이전 값으로 대신하지 않는다.
