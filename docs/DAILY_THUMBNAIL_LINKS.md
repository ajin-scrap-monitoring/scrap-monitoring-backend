# 이벤트 목록의 날짜 공통 대표 이미지

수거·알림·오류 목록은 항목의 `occurredAt`을 KST로 해석한 날짜의 대표 이미지를 공유할 수 있다. 목록·재생 상세의 `event.dailyThumbnailInfoPath`는 같은 날짜이면 같은 주소다. 이벤트 구간이 자정을 걸쳐도 이미지 선택은 발생일 기준이며 재생 구간 계산은 바뀌지 않는다. 날짜 공통 이미지를 이벤트 발생 순간의 사진으로 설명하지 않는다.

## 조회 계약

```http
GET /api/v2/recordings/daily/by-date/2026-01-02/thumbnail-info
```

로그인한 조회 사용자와 관리자 모두 사용할 수 있다. 이미지 준비·내보내기 작업이나 DB 변경을 만들지 않는다. 목록 자체는 미디어 API를 추가 호출하지 않는다. 클라이언트는 동일 경로를 중복 조회하지 않도록 현재 표시 대상에서 재사용할 수 있다.

- `200 DailyThumbnailInfo`: 기존 날짜 썸네일과 같은 `recording_id`, 상태, 크기, 시각 근거, `content_path` 계약. 바이트는 기존 `/media/daily-recordings/{recording_id}/thumbnail` 인증 경로로 조회한다.
- `200 null`: 해당 카메라·날짜의 녹화가 목록에 없다. 삭제·만료된 원본이 목록에서 제외된 경우도 포함한다. 영구적인 원본 부재나 다시 생성해야 한다는 명령으로 해석하지 않는다.
- `200 unavailable/pending/failed/unsupported`: 원본이 존재하지만 이미지가 아직 준비되지 않았거나 지원되지 않는 등 기존 상태를 그대로 전달한다. 조회만으로 준비·재시도하지 않는다.
- 삭제·만료 원본이 목록에 남아 있거나 목록 조회 후 부모가 삭제·만료되면 기존 부모 검사에 따라 `410`을 반환한다. 기존 이미지 바이트 조회도 부모 상태를 검사한다.
- `401`: 세션 없음. `422`: 잘못된 달력 날짜 또는 다음 날을 표현할 수 없는 날짜. `502`: 다른 날짜·카메라, 중복 녹화, 예상하지 못한 페이지 또는 잘못된 미디어 응답. 통신 실패·시간 초과는 기존 오류 코드로 유지하며 `null`로 숨기지 않는다.

응답은 `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`를 사용한다. 백엔드의 미디어 시간 제한은 날짜 목록과 부모·이미지 정보 조회 전체에 적용된다. 날짜당 하나의 녹화만 허용하며 요청하지 않은 날짜로 대체하지 않는다.

## 호환과 프론트 연결

기존 `thumbnailInfoPath`는 별도 추출 clip의 공유 이미지 조회 계약을 유지한다. 새로운 선택적 `dailyThumbnailInfoPath`는 날짜 공통 이미지를 위한 별도 연결이다. 날짜 이미지를 표시할 때는 이 필드를 사용하고 응답을 기존 `DailyThumbnailInfo`로 해석한다. clip ID나 이벤트 ID를 날짜 이미지 ID로 변환하지 않는다.

기존 날짜 이미지 파서·표시 위치를 재사용할 수 있다. 이미지가 없거나 날짜가 삭제되면 공통 이미지를 해제하며, 수거·알림·오류 발생 이력은 보존한다. 프론트 파서와 이미지 선택 연결은 해당 저장소 담당자가 반영해야 한다. 백엔드 반영만으로 화면 변경이 완료되는 것은 아니다.

## 지원 경계

날짜 MP4 준비 여부와 독립적으로 이미 준비된 이미지를 재사용한다. 미디어가 녹화 중 날짜의 완료된 TS에서 JPEG를 제공하면 동일한 조회 API로 표시할 수 있다. 부모 날짜의 삭제·만료·식별 검증과 이미지 상태·경로 검증은 유지하며, 별도 클립의 ready 조건은 바꾸지 않는다.

녹화를 우선해 생성이 보류되면 `unavailable/RECORDING_BUSY`를 그대로 전달한다. 이미지 바이트 조회는 기존 unavailable 규칙대로404다. 이후 준비되면 동일 경로가 ready를 반환하므로 보류를 영구 이미지 부재나 녹화 실패로 처리하지 않는다. 조회로 작업을 만들지 않으며 자동 생성·제한된 재시도는 미디어가 담당한다. 날짜 MP4 보관 중에도 기존 HLS 재생은 별도 계약대로 유지된다.

`ready`이면서 `representative_at=null`, `time_basis=null`, `reason_code=TIMELINE_UNAVAILABLE`이면 이미지 자체는 정상이다. 날짜 연결은 시각 추정 대신 부모 날짜를 사용한다. 이 응답을 이미지 미준비나 촬영 시각 검증 완료로 해석하지 않는다.

원본 삭제·만료와 날짜 썸네일 파일 정리는 기존 미디어 정책을 사용한다. 별도로 추출한 MP4·clip 이미지 또는 발생 이력을 일괄 삭제하지 않는다.
