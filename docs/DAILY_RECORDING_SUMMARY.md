# 날짜 녹화 목록 요약 조회

```http
GET /api/v2/recordings/daily?view=summary&from_date=2026-01-01&to_date=2026-01-08&limit=100
```

날짜 목록에서는 녹화 상태와 확보 길이를 표시하고, 구간별 누락과 재생 위치는 선택한
녹화 상세에서 조회한다. `view`를 생략하거나 `full`로 보내면 기존 전체 목록을 반환한다.
기존 필수 배열을 빈 배열로 바꾸지 않으며, 요약 응답에는 배열 필드 자체를 넣지 않는다.

## 응답과 화면 연결

요약 페이지는 `view: "summary"`, `items`, `next_cursor`를 반환한다. 각 항목은 기존 날짜
녹화 메타데이터와 공개 재생·다운로드 경로를 유지하며 다음 필드만 달라진다.

| 필드 | 요약 응답 |
| --- | --- |
| `gaps` | 생략. `[]`나 null로 대체하지 않음 |
| `available_intervals` | 생략. `[]`나 null로 대체하지 않음 |
| `gap_count` | 원본 누락 구간 목록의 항목 수 |
| `available_interval_count` | 원본 확보 구간 목록의 항목 수 |
| `recorded_seconds` | 기존 미디어 서비스의 확보 길이 그대로 유지 |

개수는 구간 항목 수이며 누락 시간의 합이나 프레임 수가 아니다. 시작·끝 시각이 같은
원본 구간도 항목 하나로 센다. 빈 원본 배열은 개수 0이지만, 원본 배열 누락·null·역순은
기존처럼 잘못된 미디어 응답이다. 개수 0만으로 `coverage`를 complete로 바꾸지 않는다.

목록을 `view=summary`로 조회한 뒤 녹화를 선택하면 기존
`GET /api/v2/recordings/daily/{recording_id}`로 전체 `gaps`와 `available_intervals`를 받는다.
요약 항목에 배열이 없다고 보관 영상이나 누락 구간이 없다고 해석하지 않는다.
삭제·만료 상태와 cleanup·오류 정보, 재생·다운로드 준비 여부는 기존 계약을 따른다.

## 인증과 페이지

로그인한 조회 사용자와 관리자가 사용할 수 있고 `Cache-Control: no-store`를 유지한다.
날짜 범위·상태·limit·cursor는 기존 규칙과 같다. 응답의 `next_cursor`를 그대로 사용하고
다음 페이지에도 같은 `view=summary`를 보낸다. 잘못된 view는 422다. 이 옵션은 백엔드에서
처리하며 미디어 API에 추가 매개변수로 전달하지 않는다.

카메라 ID·허용된 상대 경로·구간·시각 검증과 오류 메시지 정리는 전체 응답 검증 후 적용한다.
요약을 요청해도 녹화 생성·삭제·설정 변경·파일 검사·DB 쓰기를 추가하지 않는다.

## 개선 범위

브라우저로 보내는 구간 배열과 그 직렬화·전송·화면 처리 비용을 줄인다. 현재 미디어 API는
전체 목록을 제공하므로 미디어에서 백엔드로 오는 응답 크기와 원본 검증 비용은 남아 있다.
미디어 저장소의 수정, 구간 합치기·영상 손실 복원, 캐시나 동시 요청의 일정한 응답 시간을
보장하는 기능은 포함하지 않는다. 프론트엔드가 새 옵션을 연결해야 화면에 적용된다.
