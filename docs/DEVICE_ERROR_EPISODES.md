# 같은 장치 원인의 반복 운영 이력

compact 수신 경로에서 센서별 확정 스캔 경보를 제공하지 않는 장치 전체 상태 보고를 대상으로
같은 원인이 지속되는 동안 반복되는 운영 이벤트를 줄인다. 원본 상태 전이는 그대로 기록하고,
이미 운영 이력으로 기록한 원인의 반복에는 `diagnosticOnly=true`와
`deviceEpisodeContinuation=true`를 추가한다. 과거 행·이벤트 ID·기존 클립 참조는 수정하지 않는다.

## 원인과 구간

- 같은 장치·orchestrator 실행 인스턴스·config revision·피트 배정 안에서 기록한 원인 코드를
  기억한다. 원인 코드가 없으면 상태 이름으로 구분하며 설정 오류는 별도 상태도 구분한다.
- 새로운 원인 코드가 포함된 상태 전이는 반복으로 숨기지 않는다. 같은 상태 안의 원인 변경을
  새 전이로 만드는 기능은 이 변경에 포함하지 않는다.
- `UNKNOWN`이나 다른 오류 상태로의 전이는 정상 복귀가 아니다. 같은 원인이 다시 보고돼도
  장치 전체가 정상으로 복귀한 새 구간으로 간주하지 않는다.
- `HEALTHY`이고 원인 코드가 없는 보고를 받으면 이전 원인 기억을 비운다. 이후 재발은 새 이벤트다.
  이 조건은 보고된 정상 상태이며 물리적 복구 시각이나 새로운 시간 임계치를 만드는 것이 아니다.
- 센서별 확정 스캔 경보가 있는 보고는 기존 독립 active/recovering/clear 처리에 맡긴다.
  그 입력으로 전환하면 기존 전체 상태 보고의 억제 정보도 비운다.
- 실행 인스턴스·설정·배정이 바뀌면 이전 억제 정보를 사용하지 않는다. 첫 보고 자체로 과거
  오류의 시작을 만들거나 소급 병합하지 않는다. 첫 운영 전이의 근거가 없으면 숨기지 않는다.

예를 들어 같은 원인의 성능 저하가 측정 불가와 왕복해도, 이미 기록한 원인만 반복되는
전이는 진단 기록으로 남긴다. 중간에 다른 원인이 추가되면 그 변화는 운영 이력에 보인다.
센서별 확정 경보가 없는 보고로 각 개별 원인의 복구를 추정하지 않고 위 정상 보고까지
기록한 원인을 유지한다. 시간 버킷으로 서로 다른 장치나 원인을 한데 합치지 않는다.

## 조회와 저장

기존 운영 이력·CSV·녹화 목록 조회는 diagnosticOnly를 제외하고, 기존 자동 오류 클립
작업자는 동일하게 해당 진단 전이를 새 오류 이벤트로 처리하지 않는다.
현재 활성 알림·측정 최신성·원본 보고·구간의 기록 시각은 변경하지 않는다.

`edge_v2_latest`의 `device_error_episodes` 한 행에 범위와 최대128개 원인만 저장한다.
기존 장치 projection 잠금과 수신 트랜잭션을 사용하며 별도 migration이나 전체 이력 스캔은 없다.
원인 수가 한도를 넘거나 저장된 원인 정보가 불완전하면 운영 이벤트를 숨기는 근거로 쓰지 않는다.

이 변경은 새 장치 전체 상태 전이의 반복 노출을 줄이는 범위다. 기존 이력을 삭제하거나
DB 행 증가를 해결하는 보관 정책이 아니다. 측정값 null·입력 유효성 왕복,
새로운 성능/복귀 확인 시간, 다른 종류의 이벤트 묶음은 별도 검토한다.
계산1초·표시유지·운영지연3초·5초중앙값·손실경고 정상1시간 복귀 기준은 변경하지 않는다.
