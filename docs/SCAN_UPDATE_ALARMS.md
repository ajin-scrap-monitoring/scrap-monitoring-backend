# 스캔 갱신 지연 운영 경고

`POST /api/edge/v2/status`의 각 `sensors[]`에 선택 객체 `scan_update_alarm`을 수신한다.
기존 schema_version 2.0, 원본 스캔·판단·필터·설정은 유지한다. 새 필드가 없는 발신자는 기존
상태 판정으로 처리한다. 데이터가 오래됐다는 사실과 운영상 지연 경고 확정을 구분한다.

## 수신 계약

| 필드 | 규칙 |
| --- | --- |
| `state` | UNKNOWN / CLEAR / PENDING / ACTIVE / RECOVERING |
| `active` | UNKNOWN은 null, CLEAR·PENDING은 false, ACTIVE·RECOVERING은 true |
| `scan_age_ms` | 엣지 평가 시점의 마지막 수용 스캔 나이(ms), 유한한 0 이상 숫자 또는 null |
| `last_valid_scan_at` | 마지막 수용 스캔 획득 UTC 시각 또는 null |
| `confirm_after_ms` | 정수 3000 |
| `reason_codes` | UNKNOWN·CLEAR는 빈 배열, 나머지는 아래 상태별 단일 사유 |

PENDING은 `SCAN_UPDATE_DELAY_PENDING`, ACTIVE는 `SCAN_UPDATE_DELAY_CONFIRMED`, RECOVERING은
`SCAN_UPDATE_RECOVERING`을 사용한다. 알 수 없는 속성·잘못된 타입·서로 맞지 않는 state/active/사유
조합은 기존 422 응답으로 거부한다. 동일 ID·본문 재전송은 기존 중복 ACK 규칙을 유지한다.
서버는 엣지가 단조 시계로 계산한 운영 상태를 사용하며 HTTP 도착 간격으로 다시 계산하지 않는다.

## 활성알림

- 상태 보고가 현재 유효하고 센서의 마지막 시각·사유가 새 경고와 호환되는 경우에만 사용한다.
- CLEAR·PENDING은 스캔 지연 활성알림을 만들지 않는다. ACTIVE·RECOVERING은 센서별
  ‘LiDAR 스캔 갱신 지연’을 유지한다. A/B는 독립적으로 판단한다.
- 필드 누락·UNKNOWN·호환되지 않는 센서 상태에서는 기존 상태 처리를 유지한다. 이미 확인된
  지연이 해제되지 않았으면 ‘지연 경고 상태 확인 필요’로 남기며 정상 복귀로 바꾸지 않는다.
  확정 후 다시 PENDING이 와도 그것만으로 해제하지 않는다.
- 누적 손실·설정 오류·명시적 센서 오류·치명적 서비스 오류는 이번 유예로 숨기지 않는다.
  센서/종합 상태 보고가 오래되면 기존 상태 확인 불가 처리를 적용한다.
- 알려진 지연만으로 생긴 종합 상태 변동은 별도 스캔 지연 경고와 중복 표시하지 않는다.
  `OUTBOX_DATA_LOSS` 등 다른 종합 사유는 유지한다. 누적 손실 건수가 양수라는 이유만으로
  손실 경고를 재생성하지 않고 현재 보고 사유를 따른다.

기존 snapshot의 data_state·overall_state·센서 최신성·필터 창·적재율·수거·알림 계산은
바꾸지 않는다. 계산에 실제로 유효한 값이 없어서 나타나는 판단 불가는 별개이며 이 기능으로
정상값을 생성하거나 모든 활성알림을 제거하지 않는다. 화면의 마지막 값 3초 유지와도 별개다.

## 오류 이력과 보존

최신 상태 투영 모드에서 기존 `edge_v2_latest`에 장비별 `scan_update_alarms` 한 행으로
센서별 확정 상태를 제한해 저장한다. migration이나 새 테이블은 필요하지 않다.

PENDING→CLEAR는 지연 오류·복귀 이력을 만들지 않는다. ACTIVE/RECOVERING의 확정은 센서별
한 번만 기록하고, 이후 CLEAR를 받아야 해당 센서의 복귀를 기록한다. 반복·중복·역순 상태나
GET 조회로 이력을 늘리거나 경고를 해제하지 않는다. 발신 인스턴스·설정이 바뀌면 새 기준으로
관찰하며 이전 경고를 복구했다고 기록하지 않는다.

기존 `DEVICE_STATE_CHANGED` 진단 기록은 원래 상태와 사유를 보존한다. 양쪽 상태가 새 판정을
지원하고 지연 외의 운영 상태가 같을 때만 해당 원시 변화에 `diagnosticOnly=true`를 표시해
화면 오류 이력·안정 페이지·CSV 후보 및 자동 오류 클립에서 제외한다. 과거 기록은 소급 변경하지
않는다. 확정 지연·복귀는 같은 이벤트 종류와 기존 공개 필드 형식으로 제공하며 제목과 사유로
구분한다. 복귀는 해당 센서의 지연 경고에 한정하며 다른 장치 오류의 복구를 뜻하지 않는다.

필드 누락·UNKNOWN은 저장된 확정 경고를 해제하지 않는다. 신규 필드가 없는 구버전 및
측정 유효성 자체의 변화는 기존 처리를 유지한다. 다른 서비스의 오류 이력을 일괄 숨기지 않는다.

## 활성화 순서

1. 백엔드 변경을 병합하고 main 검사를 통과한 버전을 서버에 반영한다.
2. 수신 준비 완료를 발신자에게 전달한다.
3. 발신자 담당 범위에서 확장 전송부 적용과 전송 flag 활성화를 수행한다.
4. 실제 새 필드의 ACK·보존과 활성알림·이력을 대조한다.

코드 지원 완료만으로 실제 전송·운영 검증 완료를 주장하지 않는다. 이 저장소에서 엣지 설정이나
전송부를 변경하지 않는다. 검증은 합성 상태의 수신·중복·역순·A/B 독립 경고·명시적 복귀·
다른 오류 보존 및 기존 활성알림/이력/페이지/CSV/클립 회귀 테스트로 수행한다.
