# 이벤트 녹화 목록의 고정 페이지 조회

`GET /api/v2/recordings/events`는 기본적으로 매 요청의 최신 DB 내용을 조회한다.
`stable=true&page=1`을 추가하면 첫 조회의 이벤트 메타데이터를 고정한다.
정렬은 `occurredAt` 내림차순, 같은 시각에는 `eventId` 문자열 내림차순이다.
숫자 접미사만 비교하는 정렬이 아니다.

첫 응답의 `snapshotToken`을 다음 요청의 `snapshot_token`으로 전달한다.
`page`만 바꾸고 `category`, `pit_id`, `pageSize`, `before_seconds`,
`after_seconds`는 유지한다. `from`/`to`는 생략하거나 첫 응답의 값을 그대로
전달한다. 기간 기본값은 최근 7일, 최대 90일이며 페이지 크기는 최대 100이다.
토큰을 전달하면 `stable`을 다시 지정하지 않아도 고정 조회를 사용한다.

고정 조회에서는 이벤트 목록, 순서, 전체 건수, 이벤트 구간과 상태,
`from`, `to`, `asOf`가 유지된다. 새 이벤트, 늦게 도착한 기록,
수거 종료 갱신은 새 조회를 시작할 때 반영된다. 마지막 페이지 이후에는
기존 전체 건수와 요청 페이지를 유지한 `items=[]`를 반환한다.
기본 조회 응답에는 `snapshotToken`과 `snapshotExpiresAt`을 추가하지 않는다.

토큰은 로그인 계정에 연결된다. 최대 유효 시간은 생성 후 300초이며
`snapshotExpiresAt`으로 제공한다. 계정당 4개, 앱 프로세스당 32개,
직렬화 크기와 항목 관리 비용을 합산한 캐시 예산 32MiB를 적용한다.
용량 부족 시 오래된 목록이 먼저 제거되므로 만료 시각 전에도 사라질 수 있다.
새로고침이나 필터 변경 시 토큰 없이 1페이지부터 시작한다.

| 응답 | detail | 처리 |
| --- | --- | --- |
| 409 | `EVENT_LIST_QUERY_CHANGED` | 조건 변경 시 새 조회 시작 |
| 409 | `EVENT_LIST_SOURCE_CHANGED` | 데이터/미디어 출처 변경 시 새 조회 시작 |
| 410 | `EVENT_LIST_SNAPSHOT_GONE` | 만료·제거·재시작·다른 계정·없는 토큰. 새 조회 시작 |
| 422 | `EVENT_LIST_START_AT_FIRST_PAGE` | 토큰 없는 첫 조회는 1페이지 사용 |
| 422 | `EVENT_LIST_SNAPSHOT_TOO_LARGE` | 기간이나 유형을 좁혀 새 조회 |
| 422 | `EVENT_LIST_TIME_OUT_OF_RANGE` | 표현 가능한 시간대 포함 시각 사용 |
| 503 | `EVENT_LIST_SNAPSHOT_BUSY` | 동시 생성 제한. 잠시 후 다시 시도 |
| 503 | `EVENT_LIST_QUERY_TIMEOUT` | 기간을 좁히거나 잠시 후 다시 시도 |
| 503 | `EVENT_LIST_STORAGE_UNAVAILABLE` | 저장소 복구 후 다시 시도 |

잘못된 쿼리 형식·기간은 기존 검증과 같이 422를 반환한다.
토큰 형식은 소문자 16진수 32자다. 계정별 토큰 존재 여부는 공개하지 않는다.
첫 조회는 최대 10,000개 및 항목 비용을 포함한 8MiB까지 허용하고,
초과하면 일부만 반환하지 않고 전체 요청을 거절한다.
목록 생성은 프로세스당 동시 2개, DB 조회 제한 시간은 20초다.

캐시는 앱 프로세스 메모리에 있다. 프로세스 재시작 시 토큰은 사라진다.
여러 프로세스/서버로 확장할 때는 같은 프로세스로 요청을 보내거나 공유
저장소를 별도로 구현해야 한다. 현재 계약은 여러 프로세스 사이 토큰 공유를
보장하지 않는다. 토큰은 로그인 세션을 대체하지 않는다.

`include_playback=true`는 요청한 페이지의 복사본에 현재 미디어 메타데이터를
조회해 요약을 추가한다. 이벤트 구간과 판단 시각은 고정된 `asOf`를 사용하지만
영상 확보 상태 자체를 고정하지는 않는다. 이후 일반 페이지에는 요약을 남기지
않는다. 상세 재생 API는 현재 이벤트와 영상을 조회하므로 목록 조회 이후
상태가 바뀌거나 원본이 사라질 수 있다. 목록 고정은 영상 보존을 의미하지 않는다.
이 기능은 영상 파일 생성·복사·삭제나 전체 항목의 상세/HLS 사전 조회를 하지 않는다.
