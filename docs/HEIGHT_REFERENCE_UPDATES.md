# 재기동 없는 높이 기준 갱신

설정 저장 ACK는 설정을 보관했다는 응답이다. 바닥·센서 배치·좌표계·보정을 검증했다는 뜻이
아니므로 ACK한 revision을 높이 기준에 자동으로 대입하지 않는다. `config_revision`,
`coordinate_frame_id`, 두 센서의 보정 버전 검사는 계속 유지한다. 새 revision에서 기하가
바뀌었다면 운영자가 해당 기준을 다시 확인해야 한다.

## 최초 활성화

`EDGE_V2_HEIGHT_REFERENCE_FILE`을 비공개 JSON 파일의 컨테이너 경로로 설정한다. 그 파일의
**디렉터리**를 읽기 전용으로 마운트한다. 파일 하나만 bind mount하면 호스트에서 atomic rename한
새 파일을 컨테이너가 보지 못할 수 있다. 최초 경로·마운트 추가는 한 번의 컨테이너 재생성이 필요하고,
그 이후 기준 교체는 환경 변수 수정이나 컨테이너 재생성 없이 적용된다.

기존 `EDGE_V2_HEIGHT_REFERENCES` / `EDGE_V2_SIMULATION_HEIGHT_REFERENCES`는 시작 시 설정 검증에
사용하는 기준으로 보존한다. 파일 옵션을 지정하면 실행 중의 조회·계산은 파일 기준을 사용한다.
파일이 없거나 잘못되었다고 시작 기준이나 마지막 정상 파일로 대신 계산하지 않는다. 기존 옵션이
없는 배포는 종전 환경 변수 방식 그대로 동작한다.

디렉터리는 실행 계정만 접근하도록 `0700`, 파일은 읽기 가능한 실행 계정 소유 `0600`으로 둔다.
일반 파일만 허용하며 최종 파일의 심볼릭 링크, FIFO, 128 KiB 초과 파일과 다른 계정에 열린
파일 권한은 거부한다. 실제 배치·좌표·보정값은 Git과 공개 문서에 넣지 않는다.

## 파일 형식

아래 구조의 두 배열은 모두 필수다. 배열 원소는 기존 `HeightReference` 및
`SimulationHeightReference` 스키마를 그대로 사용한다. 빈 배열 예시는 파일 구조 설명이며,
높이 기능이 활성화된 설정에서는 유효한 기준이 반드시 필요하다.

```json
{
  "schema_version": 1,
  "height_references": [],
  "simulation_height_references": []
}
```

피트 중복·미등록 센서·기하 오류·지원하지 않는 키는 거부한다. production에서 시뮬레이션 기준을
금지하는 기존 규칙도 유지한다. 이 파일로 인증·임계치·TTL·기능 플래그를 바꿀 수 없다.

## 기준 교체

1. 저장한 새 Configuration의 센서 ID·좌표계·보정 버전 및 바닥·배치를 확인한다. revision 이름만
   바뀐 경우도 실제 설정 내용을 비교한다. 검증되지 않은 기하를 이전 숫자로 채우지 않는다.
2. 비공개 마운트 디렉터리에 `next.json`을 작성한다. 실제 실행 계정이 읽을 수 있는 소유권과
   `0600` 권한을 설정한다. 현재 파일을 직접 덮어쓰지 않는다.
3. 현재 애플리케이션의 설정으로 후보를 검사한다. 컨테이너 안의 Python 경로는 배포 이미지에
   맞게 지정한다. 명령은 파일·DB·현재 기준을 수정하지 않으며 원본 좌표를 출력하지 않는다.

   ```bash
   python -m src.app.cli.height_references --file /run/height-references/next.json
   ```

4. `valid=true`와 종료 코드 0을 확인한 뒤 같은 파일시스템에서 `next.json`을 `current.json`으로
   rename한다. 권한은 rename 전에 설정한다. 기준 복구도 검증된 이전 파일을 같은 방법으로 교체한다.
5. 다음 수신·조회부터 새 파일을 읽는다. 처리 중인 요청은 처음 선택한 기준으로 끝내므로 구기준
   좌표와 신기준 계산 ID가 섞이지 않는다. 서버가 여러 프로세스라면 각 프로세스의 다음 처리부터
   적용되며 이미 진행 중인 모든 요청이 동시에 바뀌는 것은 아니다.
6. 현재 수신 revision, 프로필의 `configRevision`, 기준 일치 사유와 null 여부를 확인한다.
   Configuration 저장 ACK만으로 완료 처리하지 않는다. 새 기준에서는 기존 시간 창을 재사용하지
   않으므로 새 실제 스캔으로 최근 창을 준비한 뒤 적재율·운영 판정을 확인한다. 정상 파일로
   교체해도 센서 단절·미보정·오래된 측정이 있으면 값은 계속 null이다.

잘못된 파일에서는 기존 API가 계산 불가/null을 제공하고 수신·상태 조회는 유지된다. 같은 경로에
올바른 파일을 교체하면 재기동 없이 다시 읽는다. CLI 검사는 파일 문법과 기존 설정 제약을 검증하며,
물리 설치 검증이나 새 Edge revision의 실수신 성공을 대신하지 않는다.

이 기능은 기준 입력 경로만 바꾼다. 계산 최신성 1초의 Edge 규칙, 화면 유지 3초, 운영 지연 경고
3초, 최근 5초 스캔 중앙값과 손실 경고의 정상 1시간 복귀를 서로 대체하지 않는다. Backend의
현재 관측 TTL은 별도 설정이며 이 변경으로 완화하거나 1초로 바꾸지 않는다.
