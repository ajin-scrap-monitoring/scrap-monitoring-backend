# Gmail 발송 전용 이메일 알림

선택적으로 Gmail API의 `gmail.send` 권한만 사용한다. Google 일반 비밀번호·앱 비밀번호·SMTP를
사용하지 않는다. 기본값은 비활성화이며, 기능을 구현·배포했다고 실제 발송이 활성화되는 것은 아니다.

이 백엔드가 보내는 알림과 관리자 테스트 메일은 발신자 표시 이름을 `Ajin_scrap_Team`으로 지정한다.
실제 발신 주소는 `GMAIL_SENDER_EMAIL`을 유지한다. Gmail 계정의 프로필 이름이나 사용자가
Gmail에서 직접 보내는 메일의 발신자 설정은 변경하지 않는다.

## 인증과 설정

Google Cloud 프로젝트에서 Gmail API와 OAuth 동의 화면을 설정한다. 일회성 Mac/Linux CLI 인증에는
Desktop OAuth client와 시스템 브라우저·로컬 콜백·PKCE를 사용할 수 있다. 서비스가 직접 웹 로그인을
제공하는 방식으로 바뀌면 그 플랫폼에 맞는 별도 client를 사용한다. 인증 코드 수동 복사 방식은 사용하지 않는다.

`gmail.send` 하나만 승인받은 authorized-user JSON을 비공개 파일로 마운트한다. 필수 값은
`client_id`, `client_secret`, `refresh_token`, `token_uri`, `scopes`다. `token_uri`는
`https://oauth2.googleapis.com/token`, scopes는 `https://www.googleapis.com/auth/gmail.send` 하나다.
파일은 서비스 실행 계정이 읽을 수 있어야 하고 다른 사용자 권한을 열지 않는다(예:0400/0600).
실제 인증 파일·토큰·발신 주소를 공개 저장소나 이미지에 포함하지 않는다.

| 설정 | 기본값·역할 |
| --- | --- |
| `GMAIL_EMAIL_ENABLED` | false. 실제 발송을 명시적으로 켬 |
| `GMAIL_CREDENTIALS_FILE` | 없음. 비공개 authorized-user JSON 경로 |
| `GMAIL_SENDER_EMAIL` | 없음. 승인한 Gmail 계정의 발신 주소 |
| `GMAIL_POLL_SECONDS` | 5초. 발송 작업 확인 간격 |
| `GMAIL_TIMEOUT_SECONDS` | 15초. 토큰 갱신/발신 HTTP 호출 각각의 전체 I/O 예산 |
| `GMAIL_MAX_MESSAGES_24H` | 450. 이 백엔드의 최근24시간 전달 작업 예산(1~500) |

토큰과 발신 주소는 DB에 저장하지 않는다. 기존 수신자 주소는 기존 수신자 테이블에서 읽고,
전달 작업에는 수신자ID·주소 변경 검사용 해시를 저장한다. 메일 본문과 전달 결과는 DB 작업에 저장한다.
접근 토큰은 메모리에서만 유지하고, 비밀값·응답 원문·메시지 본문을 오류 로그에 출력하지 않는다.
발신 계정 주소를 알아내기 위해 프로필/기존 메일 읽기 권한을 추가하지 않는다.

External/Testing OAuth 앱의 Gmail refresh token에는7일 만료 조건이 있다. 상시 가동 전에
게시 상태·계정 정책·검증 필요 여부를 확인하고 적합한 운영용 인증을 준비한다. 운영 모드에서도
권한 취소·계정 정책·비밀번호 변경 등으로 토큰이 만료될 수 있으며 재승인이 필요할 수 있다.

## 자동 알림

기존 v2 현재 알림의 판정 결과를 사용한다. 수거 필요·사전 경고·측정 오류·장치 오류를 지원하며,
카메라는 기존 원천 상태 조회가 제공하는 범위에서만 포함한다. 오래된 알림함 전체를 다시 보내지 않는다.
기존 히스테리시스·센서 수신·필터·경보 기록의 판정 알고리즘은 바꾸지 않는다.

- 수신자 활성 여부·email 채널·global/custom 유형 구독과 피트의 알림 유형을 확인한다.
- 사전 경고는 `preCollectionAlert.enabled`를 따른다. 유형 구독에서는 collection_required에 포함된다.
- 발송 지연 중 조건이 해소되거나 판정이 불명확해지면 대기 작업을 취소한다. 다시 유효해지면
  미발송 조건의 지연을 새로 계산한다. 수신자 주소가 바뀐 옛 작업은 새 주소로 보내지 않는다.
- 반복 간격은 설정값과 최소30분 중 더 긴 시간을 사용하고 최대 반복 횟수에는 첫 발송도 포함한다.
  같은 조건의 새 구간이나 재시작도 최소30분 억제를 우회하지 않는다.
- 복구 알림은 앞서 Google이 접수한 경보가 있고, 같은 출처·기준에서 조건 해소가 확인될 때만 보낸다.
  원천 변경·오래된 상태·불명확한 구간을 정상 복구로 만들지 않는다. 사전 경고→위험은 복구가 아니다.
  알림 조건 해소는 물리 장비 수리나 수거 작업 완료의 인증이 아니다.

한 번의 sweep에서 최대10개 작업을 처리하고 계속 남은 작업은 다음 sweep으로 넘긴다. 외부 요청은
DB 트랜잭션을 커밋한 뒤 별도 백그라운드 작업자가 실행하므로 장치 ACK가 Google 응답을 기다리지 않는다.
기존 운영·미디어 작업자와 같은 **단일 Uvicorn worker/단일 인스턴스** 배포가 전제다. 다중 작업자의
전역 발송 예산·전달 중 작업 복구를 제공하는 구현으로 해석하지 않는다.

## 적재율 경고 메일 표시

적재율 경고(`pre_collection_alert`)의 제목과 본문 첫 줄은
`[스크랩 모니터링] 스크랩 적재율 경고`다. 시뮬레이션 접두어를 이 메일에서만 대체한다.
비율은 소수 둘째 자리까지 버림하여 항상 두 자리로 표시한다. 판정 시각은
`판정 시각(UTC+9): YYYY-MM-DD HH:MM:SS`로 표시하고 초의 소수 부분은 생략한다.
내부 수치·UTC 저장·시뮬레이션 속성·임계치·발송 정책은 유지한다.
수거 필요·장치/측정 이상·조건 해소·수동 테스트 메일은 기존 양식을 유지한다.

## 테스트 요청과 전달 결과

기존 `POST /api/v1/notifications/test`의 관리자·CSRF 검사를 유지한다. Gmail 비활성 시 기존처럼
실제 외부 발송 없이 요청만 기록한다. 활성 상태의 email 요청은 알림 기록과 같은 트랜잭션으로
작업을 등록하고202 응답에 `emailDeliveryId`를 추가한다. 관리자 수동 테스트는 자동 알림의
사용 여부·채널 구독·유형·발송 지연과 별개로, 테스트 화면에서 명시적으로 요청한 email을 보낸다.
수신자의 자동 수신 설정은 변경하지 않는다. 발송 직전에도 수신자의 존재·현재 주소와 발송 예산을
확인하며, 수신자가 삭제되거나 주소가 바뀐 옛 요청은 취소한다. 서비스 전체의 Gmail 비활성화는
테스트에도 적용된다. SMS는 계속 기록만 하며 발송했다고 표시하지 않는다.

관리자는 `GET /api/v1/notifications/email-deliveries/{emailDeliveryId}`로 결과를 읽는다(no-store).
로그인만 한 일반 사용자는 조회할 수 없다. 이 API는 본문·수신 주소·인증 정보를 반환하지 않는다.

| 상태 | 의미 |
| --- | --- |
| QUEUED | 발송 대기 또는 명시적으로 거절된 일시 오류의 제한된 재시도 대기 |
| SENDING | Google 요청 전 DB에 시도 사실을 기록한 상태 |
| SENT | Google API가 메시지ID와 함께 접수. 받은편지함 도착·열람 확인이 아님 |
| FAILED | 인증/권한/요청 등의 명시적 실패. 같은 작업을 계속 새로 만들지 않음 |
| UNCERTAIN | 접수 여부 불명확. 자동 재발송하지 않음 |
| CANCELLED | 조건·구독·주소·현재 근거가 변경되어 취소 |

Gmail POST에는 멱등성 키가 없다. 응답 유실·5xx·성공 응답 해석 불가·전송 중 프로세스 중단은
UNCERTAIN으로 격리한다. 중복 없는 정확히 한 번 전달이나 자동 복구 완료를 보장하지 않는다.
명시적401은 토큰을 한 번 갱신해 다시 시도할 수 있고,429 및 발신 전 인증 서버 접속 장애는
대기 후 같은 작업ID로 최대3회 시도한다. Message-ID는 추적용이며 Gmail 중복 차단 보장이 아니다.
실패·불확실 상태를 재발송하기 위한 관리자 API는 이번 범위에 없다. 상태를 확인한 뒤 별도 판단한다.

최근24시간 작업 예산은 이 백엔드의 시도 기록 기준이며 Gmail 계정 전체의 남은 한도를 조회한 값이 아니다.
웹/다른 앱의 발신도 Google 한도에 영향을 준다. 개인 Gmail의500통·SMTP 수신자 제한·API 호출량 제한은
각각 구분한다. 기본450은 여유를 둔 자체 예산이며 받은편지함 도착이나 Google의 추가 제한을 보장하지 않는다.

## DB와 적용 경계

`0006_email_deliveries`는 email_episodes·email_deliveries 테이블과 인덱스를 추가한다. 기존 계정·설정·
로그·원천 데이터를 수정하지 않고 과거 알림을 메일 작업으로 일괄 생성하지 않는다. 기존22개 테이블과
합쳐24개다. 코드 적용 전에 백업·migration 절차를 따르고, 이 문서를 작성한 사실과 실제 서버 적용을 구분한다.
