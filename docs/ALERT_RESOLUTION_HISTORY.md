# 경보 이력의 활성·해제·확인 불가

일반 이벤트 이력의 경보와 기존 측정 오류를 근거 없이 모두 `resolved`로 표시하지 않는다. 앞으로 생성되는 v2 수거 필요 경보는 생성 기록과 실제 해제 판정 근거를 연결한다. 과거에 보관하지 않은 해제 여부·시각을 현재 수치로 역산하지 않는다.

## 프론트 연결 계약

`GET /api/v1/events?pit_id=...&category=alert`의 경보 상태는 다음과 같다.

| `status` | `statusBasis` | 표시 의미 |
| --- | --- | --- |
| active | CURRENT_EVALUATION | 해당 경보가 현재 유효한 위험 구간에 속함을 확인 |
| resolved | PERSISTED_RESOLUTION | 해당 위험 구간의 실제 해제 판정 근거를 보존 |
| unknown | UNVERIFIED | 과거 근거 미보관, 입력 단절, 기준 변경 등으로 해당 경보의 상태를 확정할 수 없음 |

resolved 항목은 `resolvedAt`에 작업자가 아니라 백엔드 판정 작업이 해제를 확인한 UTC 시각, `resolutionObservedAt`에 근거가 된 유효 측정의 UTC 시각을 제공한다. 센서 관측 후 처리까지 지연이 있을 수 있어 두 시각은 다를 수 있다. 최초 물리적 적재율 하락 시각을 복원한 값이 아니다. active/unknown에는 두 해제 시각이 null이다.

`GET /api/v2/monitoring/alerts?pit_id=...`에도 `lifecycle`을 추가한다. `lifecycle.state`는 ACTIVE/RESOLVED/UNKNOWN이며 resolvedAt/resolutionObservedAt의 의미는 위와 같다. 기존 triggeredAt/observedAt/readAt·알림 ID·판정 출처는 유지한다. 알림을 읽거나 전송 결과가 RECORDED/SENT라는 이유로 경보를 해제하지 않는다.

현재 활성 적재율 경보는 기존 active-alerts/snapshot의 판정을 계속 사용한다. 현재 위험 상태를 확인할 수 있어도, 근거 없는 과거 알림 한 건의 해제 여부까지 확정할 수 있는 것은 아니다. 기존 프론트는 경보 상태를 의도적으로 숨겼으므로 담당자가 unknown을 “확인 불가”로 구분하여 새 상태를 연결한다. 서버의 UTC를 유지하고 시간대 변환은 화면에서 처리한다.

## 생성·해제 근거 보존

- 유효한 위험 상태에서 새 위험 구간 식별자를 만들고, 기존 정책대로 경보가 생성될 때 알림 ID와 이 식별자를 함께 보존한다.
- 같은 위험 구간에서 기존30분 쿨다운 후 재알림이 발생하면 같은 해제 근거에 연결한다. 별도 위험 구간과는 섞지 않는다. 알림 생성 횟수와 쿨다운, 임계율·히스테리시스·지속 확인 조건은 변경하지 않는다.
- 같은 출처·계산 방법·설정·장치 부팅 구간의 유효 측정으로 CRITICAL에서 벗어났음을 백엔드가 확인한 경우에만 해제 근거를 남긴다. 기존 복귀 임계율을 그대로 따른다.
- 작업자가 확인한 입력 무효, 관측 TTL 이상의 공백, 출처·보정 기준·방법·장치 부팅·임계율 변경은 이전 위험 구간의 연결을 끊는다. 단절은 해제가 아니므로 기존 경보는 unknown으로 남는다. 나중의 새 구간 복구를 이전 구간의 해제 시각으로 채우지 않는다.
- 이전 버전에서 생성해 근거가 없는 경보도 unknown이다. 현재 상태가 NORMAL이라는 사실만으로 과거 시각을 만들지 않는다.
- 조회 시 active는 현재 FRESH 입력·유효한 CRITICAL 판정·같은 위험 구간과 기준을 함께 확인한 경우만 제공한다. 판정 작업 중지·오래된 측정·다른 피트/장치의 정보로 활성 여부를 확정하지 않는다.
- 이미 보존한 해제 근거는 현재 측정의 단절이나 설정 변경 뒤에도 과거 사실로 조회한다. 관리자의 수거 완료 기록과 혼합하지 않는다.

기존 edge_v2_latest에 작은 현재 구간 포인터만, edge_v2_transitions에 ALERT_CREATED/ALERT_RESOLVED 근거만 보존한다. 현재 포인터에 알림 ID 목록이나 원시 측정을 누적하지 않는다. 경보·판정 커서와 같은 트랜잭션으로 저장하므로 재시도나 중복 측정이 같은 판정을 중복 기록하지 않는다. 기존 단일 작업자 운영 조건을 따른다. 새 테이블·마이그레이션·원시 스캔 이력은 추가하지 않는다. 이 기능은 별도 경보·이메일·녹화·수거 완료 기록을 생성하지 않는다.

## 다른 이벤트와의 구분

v2 장치·측정 입력 변화의 `statusBasis=AT_OCCURRENCE`는 [오류·복구 이력](ERROR_RECOVERY_HISTORY.md)의 기록 당시 상태다. 이 작업에서 해당 상태를 현재 경보 수명으로 바꾸지 않는다. 기존 ScrapMetric 오류의 복구 근거는 없으므로 status=unknown/해제 시각null을 제공한다. 관리자 수거 완료의 completed 상태는 실제 확인 기록으로 유지한다.

이 문서를 LiDAR A→B, 예측·평균 주기, 전체 수거 이력 범위 및 한국시간 표시 안내와 함께 프론트 담당자에게 전달한다.
