# v2 이벤트 영상 연결

`MEDIA_V2_EVENT_CLIPS_ENABLED=true`이면 기존 미디어 작업자가 새 v2 이벤트를 영상 요청과 연결한다. 기본값은 false이며 미디어 저장 용량과 녹화 정책을 확인한 뒤 활성화한다. 센서 수신·판정 작업자나 조회 API에서 미디어 HTTP 요청을 보내지 않는다. 백엔드는 JSON만 처리하고 영상 바이트는 기존 게이트웨이를 사용한다.

## 녹화 유형

| 유형 | 연결 기준 | 이벤트 식별자 |
| --- | --- | --- |
| 알림 | 실제 생성된 v2 수거 필요 경보 | 기존 `evt-alt-{alert_id}` |
| 수거 | 수거 시작 감지 | `evt-auto-col-start-{transition_id}` |
| 오류 | 장치 측정 중단·설정 오류, 준비 상태를 제외한 측정 입력 사용 불가 | 기존 `evt-v2-transition-{transition_id}` |

복구·준비·단순 성능 저하는 새 오류 영상을 생성하지 않는다. 경보는 기존 30분 쿨다운을 그대로 따르고, 자동 수거 종료를 사람의 완료 확인으로 바꾸지 않는다. 같은 카메라·이벤트는 기존 outbox와 미디어 서비스의 멱등 키를 재사용한다. 오류는 `/api/v1/recordings?category=error`에서 오류로 분류한다.

이력의 경보·오류 항목은 기존 이벤트 ID로 `recordingId`를 연결한다. 수거 종료 이력은 시작과 종료의 피트·현장·장치·감지 기준·`detectionId`가 같은 경우에만 시작 영상으로 연결한다. 겹치는 시각만으로 연결하지 않는다. 미디어가 아직 접수하지 않은 요청에는 가짜 영상 ID를 만들지 않는다.

## 수거 시작부터 종료 감지까지

수거는 시작 감지 시점에 영상 요청을 보내며, 동일한 수거 구간의 종료 감지 기록을 읽어 다음 필드를 제공한다.

| `/api/v1/recordings` 필드 | 의미 |
| --- | --- |
| `eventOccurredAt` | 이벤트 발생 시각. 수거는 시작 감지 UTC |
| `eventEndedAt` | 같은 수거 구간의 종료 감지 UTC. 진행 중·단절·근거 부족은 null |
| `eventWindowCovered` | 준비된 영상 메타데이터가 시작→종료 구간 전체를 포함하는지 여부. 범위 밖·구간 내 누락은 false, 전체 포함 근거가 충분하면 true, 종료 미확인·준비 중·불확실한 부분 저장은 null |
| `eventSimulated` | 시뮬레이션 이벤트 여부. 과거 미보관·출처 불명은 null. 영상 자체의 촬영 장치 검증을 뜻하지 않음 |

기존 `startedAt/endedAt`은 영상 요청 구간이며 수거 시작·종료 시각과 다를 수 있다. 종료 감지는 추가 감소가 없는 대기 조건에 따른 판정으로, 물리적 기계팔 동작의 정확한 시작·끝을 보장하지 않는다.

**현재 미디어 API는 수거 전체 구간을 동적으로 저장하는 기능을 제공하지 않는다.** POST 클립 요청은 camera_id/event_id만 받고, 최초 접수 시각의 앞뒤 고정 길이를 저장한다. 각 pre/post 값은 최대300초이며 기본30초다. 수거 중 종료 시각을 연장하거나 종료 감지에 맞춰 닫는 API는 없다. 수거 시작 영상이 준비됐다는 사실을 전체 수거 영상 완료로 표시하지 않는다. 짧은 영상은 `eventWindowCovered=false`일 수 있다.

전체 구간 영상을 완성하려면 미디어 담당 측에 다음 기능이 필요하다. 아래는 추가 연동 요구이며 현재 확정·구현된 API가 아니다.

- 안정적인 수거 식별자로 시작 요청을 받고 해당 시점부터 영상 보존.
- 같은 식별자의 종료 감지 시각으로 구간 확정. 장시간 수거·추가 감소 없는 대기 시간도 처리.
- 중복 시작/종료, 네트워크 재시도·재시작·종료 누락 처리와 보관 용량 정책.
- 실제 확보 구간·누락·처리 상태·다운로드 경로 반환. 종료 연장 또는 저장된 날짜 영상의 특정 구간 추출 중 구현 방식은 담당자와 계약 확정 필요.

백엔드는 시작·종료 연결 정보를 준비하지만, 위 미디어 기능 없이 전체 구간 촬영을 완료했다고 응답하지 않는다. 날짜 녹화의 하루 MP4 준비 API도 임의 수거 구간 추출 API로 간주하지 않는다.

## 시작·재시도와 지연 제한

- 작업자 시작·재시작·재활성화·카메라/피트/출처 변경 시 기존 이력을 새로 촬영하지 않고 현재 기준점을 만든다. 이미 큐에 저장한 요청은 유지한다.
- `MEDIA_V2_EVENT_CLIP_MAX_DELAY_SECONDS`는 새 요청을 보낼 수 있는 최대 지연이며 기본30초, 1~300초다. 현재 활성화 이후의 같은 출처·피트 이벤트만 처리한다. 미래 이벤트를 현재 시각의 영상으로 요청하지 않는다.
- DB ID는 커밋 전에 배정될 수 있어 작은 ID가 늦게 나타날 수 있다. 활성화 기준점과 최근 시간창을 함께 사용하고 기존 outbox를 제외해 누락·중복을 막는다. 한 번에 최대20건을 큐에 추가하고 최대1000개 작은 이벤트 후보만 확인한다.
- 센서 ACK와 분리된 트랜잭션에서 요청 정보를 저장한다. 카메라 주소·토큰 원문이나 원시 스캔은 새로 저장하지 않는다. 새 테이블·마이그레이션은 없다.
- 지연 한도를 넘긴 미접수 자동 요청은 `EVENT_CLIP_WINDOW_EXPIRED`로 중단한다. 현재 영상을 과거 영상으로 만들지 않는다.
- 생성 응답을 잃었으면 늦은 POST 대신 동일 카메라·이벤트의 GET 조회로 이미 접수된 영상을 복원한다. 미접수였으면 새 영상을 만들지 않는다. 소스가 바뀌면 다른 미디어 서비스에 복원 요청하지 않는다.
- 기능을 끄면 새 자동 생성 요청을 막고, 이미 접수된 클립은 계속 조회할 수 있다. 기존 수동 수거 확인·기존 경보 엔진의 동작은 유지한다.

녹화 정책의 pre/post/retention, 날짜 녹화, 미디어 저장 용량은 이 기능이 변경하지 않는다. 실제 활성화·현장 영상 품질·수거 구간 정답 대조는 별도 검증 대상이다.

## 활성화 후 구버전 복구

기본 비활성 상태에서는 새 v2 요청이 생성되지 않는다. 활성화 후에는 미접수 요청의 로컬 대기 메타데이터와 지연 제한을 모르는 구버전으로 바로 교체하지 않는다. 먼저 미디어 작업자를 멈추고, 미접수 v2 요청을 보존·중단 처리해 구버전이 늦은 POST를 실행하지 않도록 확인한다. 구버전의 대기 메타데이터 호환성도 함께 처리해야 한다. 이미 접수된 영상·기존 이벤트 원본은 삭제하지 않는다.

## 상시 영상 공유 방식

추가 클립을 생성하지 않고 기존 날짜 영상의 이벤트 구간을 조회하려면 [이벤트 구간 재생](EVENT_RECORDING_REFERENCES.md)을 따른다. 이 방식은 읽기 전용이며 기존 자동 클립 설정을 켤 필요가 없다.
